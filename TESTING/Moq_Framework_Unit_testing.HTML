Moq Framework — Beginner's Guide (C#)

A concise, hands-on introduction to using Moq for unit testing in C#.

What is Moq?

Moq is a popular, simple-to-use mocking library for .NET that helps you create mock objects for unit tests. It's most commonly used with test frameworks like xUnit, NUnit, or MSTest.

Why mock?

  • Isolate the unit under test (class/method) from external dependencies (DB, web services, file system).
  • Control dependency behavior (return values, exceptions).
  • Verify interaction (was a method called? how many times?).

Install Moq

Using the .NET CLI:

dotnet add package Moq

Or using NuGet Package Manager Console:

Install-Package Moq

Basic example — Arrange/Act/Assert

Suppose you have a service that depends on an interface:

// Production code
public interface IEmailSender
{
  void Send(string to, string subject, string body);
}

public class WelcomeService
{
  private readonly IEmailSender _emailSender;
  public WelcomeService(IEmailSender emailSender) => _emailSender = emailSender;

  public void SendWelcome(string userEmail)
  {
    var subject = "Welcome!";
    var body = "Thanks for joining.";
    _emailSender.Send(userEmail, subject, body);
  }
}

Unit test with Moq:

// Test code (xUnit)
using Moq;
using Xunit;

public class WelcomeServiceTests
{
  [Fact]
  public void SendWelcome_CallsEmailSender()
  {
    // Arrange
    var mockEmail = new Mock();
    var service = new WelcomeService(mockEmail.Object);

    // Act
    service.SendWelcome("alice@example.com");

    // Assert - verify that Send was called once with those parameters
    mockEmail.Verify(m => m.Send("alice@example.com", "Welcome!", "Thanks for joining."), Times.Once);
  }
}

Setup & Returns

Use Setup to configure mock behavior and Returns to provide a return value:

public interface IUserRepository { User GetById(int id); }

var mockRepo = new Mock();
mockRepo.Setup(r => r.GetById(5)).Returns(new User { Id = 5, Name = "Ben" });

var user = mockRepo.Object.GetById(5);
// user.Name == "Ben"

It.Is & It.IsAny

For flexible matching of arguments:

mockRepo.Setup(r => r.GetById(It.IsAny()))
        .Returns((int id) => new User { Id = id, Name = "User" + id });

// Or match predicate:
mockRepo.Setup(r => r.GetById(It.Is(i => i > 0))).Returns(new User());

Verifying calls

  • Verify — check a method was called with particular arguments.
  • Times.Once, Times.Never, Times.AtLeastOnce, etc.
mock.Verify(m => m.DoSomething(), Times.Exactly(2));

Exceptions and Throws

mock.Setup(m => m.Process(It.IsAny<string>()))
    .Throws(new InvalidOperationException("bad input"));

Callbacks

Use callbacks to inspect arguments or change state when a mock method is called:

string captured = null;
mock.Setup(m => m.Send(It.IsAny<string>(), It.IsAny<string>(), It.IsAny<string>()))
    .Callback((string to, string subject, string body) => captured = to);

// After action, captured will hold the 'to' value

Mocking properties

By default, mocks don't store property values. Use SetupProperty or SetupAllProperties:

var mock = new Mock<IUser>();
mock.SetupProperty(u => u.Name);
mock.Object.Name = "Sam";
// Now mock.Object.Name returns "Sam".

// Or automatically for all properties:
mock.SetupAllProperties();

Partial mocks (classes)

You can mock concrete classes, but only virtual/abstract members are mockable:

public class Greeter
{
  public virtual string Hello() => "Hello";
}

var mock = new Mock<Greeter>();
mock.Setup(g => g.Hello()).Returns("Hi");

Mock behaviors

Loose (default): Calls that aren't set up return default values.
Strict: Any call not explicitly set up throws MockException.

var strictMock = new Mock<IService>(MockBehavior.Strict);
strictMock.Setup(s => s.DoStuff());
// Any other call will throw

Async methods

For methods returning Task or Task<T>:

mock.Setup(m => m.GetAsync(1)).ReturnsAsync(new User { Id = 1 });

mock.Setup(m => m.DoWorkAsync()).Returns(Task.CompletedTask);

Common pitfalls & tips

  • Mock interfaces or abstract classes — avoid mocking concrete implementation details when possible.
  • Don't overuse mocks — for simple data objects use real instances.
  • Keep tests small and focused: one behavior per test.
  • When mocking dependencies, prefer testing behavior (calls, outcomes) over internal implementation.
  • Use It.IsAny<T>() sparingly — precise argument checks catch bugs earlier.

Example — full test (xUnit)

public class OrderProcessorTests
{
  [Fact]
  public void Process_Order_SendsEmailAndMarksProcessed()
  {
    // Arrange
    var order = new Order { Id = 1 };
    var repo = new Mock<IOrderRepository>();
    repo.Setup(r => r.Get(1)).Returns(order);

    var email = new Mock<IEmailSender>();

    var processor = new OrderProcessor(repo.Object, email.Object);

    // Act
    processor.Process(1);

    // Assert
    repo.Verify(r => r.Save(It.Is<Order>(o => o.Processed == true)), Times.Once);
    email.Verify(e => e.Send(It.IsAny<string>(), It.IsAny<string>(), It.IsAny<string>()), Times.Once);
  }
}
Quick cheatsheet
  • new Mock<T>() — create a mock.
  • .Object — instance to pass to the SUT (system under test).
  • Setup() — define behavior.
  • Returns() / ReturnsAsync() — supply return values.
  • Verify() — assert interactions.
  • It.IsAny<T>() / It.Is<T>(predicate) — argument matching.
