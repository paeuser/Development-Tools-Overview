20 Tricky SQL Server Performance Questions & Answers

  • 22. What is the difference between a Stored Procedure and a Function in SQL Server?
    Stored Procedure:
    - Performs actions or series of operations.
    - Can modify data (INSERT, UPDATE, DELETE).
    - Can return multiple values using OUTPUT parameters or RETURN (integer only).
    - Cannot be used directly in SELECT, WHERE, or JOIN.
    - Can use transactions (BEGIN TRAN, COMMIT, ROLLBACK).

    Function:
    - Returns a single value (scalar) or a table (table-valued function).
    - Generally does not modify database state.
    - Can be used in SELECT, WHERE, JOIN, or inside another function.
    - Cannot include transaction control statements.

    Key Takeaway: Use stored procedures for actions and business logic; use functions to return reusable values in queries.
  • 21. What does the NOLOCK hint do, and what are its risks?
    The NOLOCK hint allows reading data without acquiring shared locks, which reduces blocking and can improve read performance in high-concurrency systems.
    Risks: Can read uncommitted (dirty) data, potentially returning inconsistent results, phantom reads, or duplicate rows.
  • 1. What is the impact of using SELECT * vs specifying columns explicitly in large tables?
    Using SELECT * retrieves unnecessary data, increasing I/O, network traffic, and reducing query performance. Always specify needed columns.
  • 2. How does indexing affect write-heavy tables, and when can indexes hurt performance?
    Indexes improve read performance but slow down INSERT, UPDATE, DELETE operations because indexes need to be maintained. Too many indexes on write-heavy tables hurt performance.
  • 3. What is the difference between clustered and non-clustered indexes in query performance?
    Clustered index defines physical order of data (good for range queries). Non-clustered indexes are separate structures, useful for lookups. Wrong choice can cause scans.
  • 4. How does parameter sniffing affect query execution plans?
    SQL Server may optimize queries based on first parameter value. If later values are different, performance may degrade. Use OPTION (RECOMPILE) or plan guides to mitigate.
  • 5. What is the role of execution plans, and how can you analyze a slow query?
    Execution plans show how SQL Server executes a query. Analyze Index Seek vs Scan, joins, costs. Use SET STATISTICS IO/TIME or execution plan in SSMS.
  • 6. How does using temporary tables vs table variables impact performance?
    Temp tables can have indexes and statistics; better for large datasets. Table variables have no statistics, may lead to suboptimal plans for big data.
  • 7. What are the effects of excessive joins on large tables?
    Too many joins increase query complexity, memory usage, and can cause table scans. Use proper indexing, consider splitting queries.
  • 8. When is using a CTE (Common Table Expression) worse for performance?
    CTEs are good for readability but may re-evaluate each reference in recursive or complex queries. Temp tables can be more efficient.
  • 9. How does statistics update affect query optimization?
    Outdated statistics can lead to bad execution plans. SQL Server uses statistics to estimate row counts; update them for better query performance.
  • 10. What are the dangers of using cursors for data processing?
    Cursors process row by row (slow). They increase memory and CPU usage. Use set-based operations instead.
  • 11. How does database fragmentation affect read/write operations?
    Fragmented indexes cause more I/O and slower reads. Regular index rebuilds or reorganizations improve performance.
  • 12. What is the difference between covering indexes and included columns?
    Covering index includes all columns needed for a query (avoiding lookups). Included columns store extra columns in the index leaf for better performance.
  • 13. How does using OR conditions vs UNION ALL affect performance?
    OR in WHERE can prevent index usage. Splitting queries with UNION ALL often improves performance.
  • 14. What is the impact of large IN lists in queries?
    Large IN lists can slow queries. Using temp tables or joins is better for performance.
  • 15. How can blocking and deadlocks be minimized in high-concurrency environments?
    Use proper indexing, smaller transactions, row-level locking, and avoid long-running transactions.
  • 16. What are the best practices for avoiding table scans in large tables?
    Create appropriate indexes, filter using indexed columns, avoid functions on indexed columns.
  • 17. How does the use of functions in WHERE clauses affect indexing?
    Using functions on indexed columns disables index usage. Rewrite queries to avoid functions on the column.
  • 18. What is the difference between eager vs lazy loading in SQL Server?
    Eager loads data upfront (less round-trips). Lazy loads only when needed (less initial load). Choose based on query pattern to avoid unnecessary reads.
  • 19. How does row-level locking vs page-level locking affect performance?
    Row-level reduces contention but more overhead. Page-level is faster but can block unrelated rows. SQL Server chooses automatically.
  • 20. When should you use tempdb efficiently to avoid performance bottlenecks?
    Tempdb is shared for temp tables, table variables, sorts. Avoid excessive temp objects, spread across multiple files, monitor for contention.
