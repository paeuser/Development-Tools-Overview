SQL Server Query Store — Demo & Quick Start

What is Query Store?

Query Store records query text, execution plans, and runtime statistics so you can analyze performance trends over time, identify regressions, and force known-good plans. It was introduced in SQL Server 2016.

Quick enable (run on the database you want to monitor)

Run these statements in SSMS or any T-SQL client as a user with ALTER DATABASE rights:


-- enable Query Store on an existing database
ALTER DATABASE [YourDatabaseName]
SET QUERY_STORE = ON;

-- Recommended basic configuration (adjust as needed)
ALTER DATABASE [YourDatabaseName]
SET QUERY_STORE (OPERATION_MODE = READ_WRITE, CLEANUP_POLICY = (STALE_QUERY_THRESHOLD_DAYS = 30),
                 INTERVAL_LENGTH_MINUTES = 60, MAX_STORAGE_SIZE_MB = 1000,
                 QUERY_CAPTURE_MODE = AUTO);
Tip: You can also enable Query Store when you create a database via CREATE DATABASE ... WITH (QUERY_STORE = ON ...)

Self-contained demo: create DB, seed data, run queries, inspect Query Store

The block below creates a demo DB called QueryStoreDemo, populates a table, executes two query patterns repeatedly to generate history, and then shows sample queries against the Query Store DMVs.


-- 1) Create demo database and enable Query Store
IF DB_ID('QueryStoreDemo') IS NOT NULL
  DROP DATABASE QueryStoreDemo;
GO

CREATE DATABASE QueryStoreDemo;
GO

ALTER DATABASE QueryStoreDemo
SET QUERY_STORE = ON;

ALTER DATABASE QueryStoreDemo
SET QUERY_STORE (OPERATION_MODE = READ_WRITE, QUERY_CAPTURE_MODE = AUTO, MAX_STORAGE_SIZE_MB = 200);
GO

USE QueryStoreDemo;
GO

-- 2) Create a sample table and insert rows
CREATE TABLE dbo.OrdersDemo
(
  OrderId INT IDENTITY PRIMARY KEY,
  CustomerId INT NOT NULL,
  OrderDate DATETIME NOT NULL,
  Amount DECIMAL(10,2) NOT NULL,
  Status CHAR(1) NOT NULL
);

-- insert a reasonable number of rows to make plans matter
SET NOCOUNT ON;
DECLARE @i INT = 1;
WHILE @i <= 20000
BEGIN
  INSERT INTO dbo.OrdersDemo (CustomerId, OrderDate, Amount, Status)
  VALUES ((ABS(CHECKSUM(NEWID())) % 1000) + 1,
          DATEADD(day, -ABS(CHECKSUM(NEWID())) % 365, GETDATE()),
          ROUND(ABS(CHECKSUM(NEWID())) % 10000 / 100.0, 2),
          CASE WHEN (ABS(CHECKSUM(NEWID())) % 3) = 0 THEN 'C' ELSE 'O' END);
  SET @i += 1;
END;
GO

-- 3) Create an index that will help one query pattern
CREATE INDEX IX_OrdersDemo_CustDate ON dbo.OrdersDemo(CustomerId, OrderDate);
GO

-- 4) Run two different query patterns multiple times to populate Query Store
-- Pattern A: parameterized-like (simulate same query shape many times)
DECLARE @k INT;
SET @k = 1;
WHILE @k <= 30
BEGIN
  -- Query pattern A: by customer id (uses index)
  SELECT CustomerId, COUNT(*) AS OrdersCount, SUM(Amount) AS TotalAmount
  FROM dbo.OrdersDemo
  WHERE CustomerId = (ABS(CHECKSUM(NEWID())) % 1000) + 1
  GROUP BY CustomerId;

  -- Query pattern B: range scan on date (may produce different plan)
  SELECT COUNT(*) AS RecentOrders
  FROM dbo.OrdersDemo
  WHERE OrderDate >= DATEADD(day, -30, GETDATE())
    AND Amount < 500;  -- intentionally simple filter

  SET @k += 1;
END;
GO

-- 5) Query Query Store DMVs for top-consuming queries
-- top queries by average duration
SELECT TOP 20
  qt.query_text_id,
  qt.query_sql_text,
  qs.query_id,
  rs.avg_duration,
  rs.max_duration,
  rs.count_executions,
  p.plan_id
FROM sys.query_store_query_text qt
JOIN sys.query_store_query q ON qt.query_text_id = q.query_text_id
JOIN sys.query_store_plan p ON q.query_id = p.query_id
JOIN (SELECT plan_id,
             AVG(avg_duration) OVER (PARTITION BY plan_id) AS avg_duration,
             MAX(max_duration) OVER (PARTITION BY plan_id) AS max_duration,
             SUM(count_executions) OVER (PARTITION BY plan_id) AS count_executions
      FROM sys.query_store_runtime_stats) rs ON p.plan_id = rs.plan_id
ORDER BY rs.avg_duration DESC;
GO

-- 6) Show plans for a specific query_id (replace 1 with the query_id you found)
SELECT qsq.query_id, qsqt.query_sql_text, p.plan_id, p.is_forced_plan
FROM sys.query_store_query qsq
JOIN sys.query_store_query_text qsqt ON qsq.query_text_id = qsqt.query_text_id
JOIN sys.query_store_plan p ON qsq.query_id = p.query_id
WHERE qsq.query_id = 1;   -- change as needed
GO

-- 7) (Optional) Force a specific plan for a query (use valid query_id and plan_id from the results above)
-- Example:
-- EXEC sp_query_store_force_plan @query_id = 1, @plan_id = 3;
-- To unforce:
-- EXEC sp_query_store_unforce_plan @query_id = 1, @plan_id = 3;
Notes:
  • Replace the hard-coded query_id and plan_id with the IDs you discover from the DMV queries.
  • If you get NULL rows in the Query Store queries, increase the number of sample executions or lower capture thresholds.

Helpful Query Store DMV views (quick reference)


-- Query text and IDs
SELECT * FROM sys.query_store_query_text;

-- Queries (logical queries)
SELECT * FROM sys.query_store_query;

-- Plans
SELECT * FROM sys.query_store_plan;

-- Runtime stats per plan
SELECT * FROM sys.query_store_runtime_stats;

-- Aggregated runtime stats (per plan)
SELECT * FROM sys.query_store_runtime_stats_interval;

Common interview talking points

  • Query Store is persistent and great for diagnosing regressions that happened earlier (unlike short-live traces).
  • You can review historical plans and metrics, and force a plan if the optimizer regresses to a bad plan.
  • Monitor storage usage of Query Store and tune MAX_STORAGE_SIZE_MB and cleanup policy as needed.
  • Query Store may slightly increase overhead; tune capture mode (AUTO, ALL, NONE) based on workload.

Cleanup / turning it off


-- To disable Query Store (it keeps captured data until you purge it)
ALTER DATABASE QueryStoreDemo SET QUERY_STORE = OFF;

-- To clear all Query Store data
ALTER DATABASE QueryStoreDemo SET QUERY_STORE CLEAR ALL;
