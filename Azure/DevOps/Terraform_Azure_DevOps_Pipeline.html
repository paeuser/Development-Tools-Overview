Terraform + Azure DevOps Pipeline — Beginner Walkthrough

A friendly, step-by-step HTML guide that states the plan first and then shows each step so a beginner can reproduce the demo: use Terraform to create Azure DevOps project resources, then use an Azure DevOps YAML pipeline to run Terraform that provisions an Azure virtual network.

Plan (What we'll accomplish)

  1. Create an Azure DevOps project and supporting resources (service connection to GitHub, variable group).
  2. Provision an Azure Storage Account and container to use as a remote state backend (SAS or account key).
  3. Store pipeline variables (including secrets) in an Azure DevOps variable group.
  4. Create an Azure DevOps YAML pipeline in the repository (validate > plan > manual approve > apply).
  5. Use Terraform Cloud (or another remote state) for the setup run that provisions the DevOps resources.
  6. Run the pipeline to deploy a simple Azure VNet with two subnets (as a reproducible example).
Tip: do this in a test subscription first. Keep production credentials separate and use Key Vault later.

Prerequisites

  • An Azure subscription and an account with permission to create resources (storage, resource groups, service principals).
  • An Azure DevOps organization (https://dev.azure.com/yourorg) and a Personal Access Token (PAT) with appropriate scopes.
  • A GitHub repo (or Azure Repos) that will host the Terraform configuration and the azure-pipelines.yml.
  • Terraform installed locally for testing (optional) and a Terraform Cloud account if you want remote runs for the setup step.

Recommended repository structure

/ (repo root)
  ├─ setup/                # Terraform code that creates the Azure DevOps project + storage account
  │   ├─ main.tf
  │   ├─ variables.tf
  │   └─ outputs.tf
  ├─ v-net/                # Terraform code deployed by the pipeline
  │   ├─ main.tf
  │   ├─ variables.tf
  │   └─ outputs.tf
  └─ azure-pipelines.yml   # Pipeline that runs terraform in v-net/

High-level steps (summary)

  1. Write Terraform in setup/ to create Azure DevOps project, service connection (GitHub), variable group, storage account, container, and SAS token.
  2. Run the setup Terraform (e.g., from Terraform Cloud workspace) — this creates the DevOps objects needed for the pipeline.
  3. Create a YAML pipeline file in the repo that uses the variable group and executes Terraform CLI commands (init/plan/apply) for v-net/.
  4. Push a change to the v-net folder to trigger the pipeline or run it manually. Review the plan, approve, and apply.

Key Terraform snippets (setup)

Below are condensed examples — adapt names, locations and credentials to your environment.

Providers (in setup/terraform.tf)

terraform {
  required_providers {
    azuredevops = { source = "microsoft/azuredevops" }
    azurerm      = { source = "hashicorp/azurerm" }
  }
  backend "remote" { # terraform cloud or another remote
    organization = "your-tf-cloud-org"
    workspaces { name = "ado-setup-workspace" }
  }
}

provider "azuredevops" { org_service_url = var.ado_org_url }
provider "azurerm" { features = {} }

Create an Azure DevOps project + enable pipelines

resource "azuredevops_project" "project" {
  name               = local.project_name
  description        = "Project created by Terraform"
  visibility         = "private"
  version_control    = "Git"
  work_item_template = "Agile"
}

Create storage account + container (for backend)

resource "azurerm_resource_group" "rg" { name = "rg-terraform-setup" location = var.location }
resource "azurerm_storage_account" "sa" { name = local.sa_name resource_group_name = azurerm_resource_group.rg.name location = var.location account_tier="Standard" account_replication_type="LRS" }
resource "azurerm_storage_container" "container" { name = var.container_name storage_account_name = azurerm_storage_account.sa.name }

# Optionally create a SAS token, then store it in azuredevops variable group

Variable group & secrets

Create a variable group in Azure DevOps and add variables: storage account name, container, key, client_id, client_secret, subscription_id, tenant_id, and any other values your Terraform needs. Mark sensitive values as secret.

Note: currently some providers require the GitHub PAT to be a non-environment variable — check provider docs. If needed, store PAT in a plain pipeline variable marked as secret inside the variable group.

Sample Azure DevOps pipeline (azure-pipelines.yml)

This pipeline uses stages: validate, plan, approval, apply. It reads variables from the variable group created by setup.

trigger:
  branches:
    include:
      - main
  paths:
    include:
      - v-net/*

variables:
  - group: 'terraform-tuesday'   # name of your variable group

stages:
- stage: Validate
  jobs:
  - job: validate
    pool:
      vmImage: 'ubuntu-latest'
    steps:
    - task: UseTerraform@0
      inputs:
        command: init
        workingDirectory: 'v-net'
    - script: |
        terraform -chdir=v-net validate
      displayName: 'terraform validate'

- stage: Plan
  dependsOn: Validate
  jobs:
  - job: plan
    pool:
      vmImage: 'ubuntu-latest'
    steps:
    - script: |
        terraform -chdir=v-net init -backend-config="storage_account_name=$(storageAccountName)" -backend-config="container_name=$(containerName)" -backend-config="key=$(stateKey)"
        terraform -chdir=v-net plan -out=tfplan
      displayName: 'terraform plan'
    - publish: v-net/tfplan
      artifact: tfplan

- stage: Approval
  dependsOn: Plan
  jobs:
  - deployment: ManualApproval
    pool: server
    environment: 'none'
    strategy:
      runOnce:
        deploy:
          steps:
          - task: ManualValidation@0
            inputs:
              instructions: 'Review the plan artifact and approve to continue.'

- stage: Apply
  dependsOn: Approval
  jobs:
  - job: apply
    pool:
      vmImage: 'ubuntu-latest'
    steps:
    - download: current
      artifact: tfplan
    - script: |
        terraform -chdir=v-net apply -auto-approve tfplan
      displayName: 'terraform apply'
Tip: prefer stashing the plan file and applying the same plan file to avoid drift between plan and apply.

Run examples (local vs CI)

  1. Locally (optional): terraform init & terraform plan -out=tfplan & terraform apply tfplan.
  2. From Azure Pipelines: push a change to v-net/ and the YAML pipeline will trigger (if triggers are configured).
  3. Review plan output in the pipeline UI and approve the manual stage to apply.

Best practices & next improvements

  • Use Key Vault to store secrets and reference them in the pipeline.
  • Pin Terraform versions in pipelines to avoid surprises from new releases.
  • Create separate pipelines for PR validation and for main-to-production deployments.
  • Run security scans (eg. Checkov or tfsec) as part of validation stage.
  • Store and apply a binary plan file between plan & apply to ensure consistency.
