async/await (.NET / C#)

In C#, async/await is used to write asynchronous code that is easy to read and maintain. It allows tasks to run without blocking the main thread, which is especially useful for I/O operations, web requests, or database calls.

Why use async/await?

  • Keeps the UI responsive in desktop or web applications
  • Makes asynchronous code look like synchronous code
  • Provides simple error handling with try/catch

Basic Example:

// Example: Fetching data asynchronously
using System;
using System.Net.Http;
using System.Threading.Tasks;

class Program
{
    static async Task Main()
    {
        try
        {
            string result = await GetDataAsync();
            Console.WriteLine(result);
        }
        catch (Exception ex)
        {
            Console.WriteLine("Error: " + ex.Message);
        }
    }

    static async Task<string> GetDataAsync()
    {
        using HttpClient client = new HttpClient();
        string response = await client.GetStringAsync("https://api.example.com/data");
        return response;
    }
}

Explanation:

  • async marks a method as asynchronous.
  • await pauses the execution until the awaited task completes.
  • Tasks (Task) represent asynchronous operations.
  • Errors can be handled with try/catch like synchronous code.

Dependency Injection

Dependency Injection (DI) is a design pattern used to provide a class with its dependencies rather than creating them itself. In Angular, DI allows you to inject services or other classes into components, making your code more modular, testable, and maintainable.

Why use Dependency Injection?

  • Reduces tight coupling between components and services
  • Makes it easier to reuse and test code
  • Provides a centralized way to manage services

    Service Lifetimes in .NET

    In .NET (ASP.NET Core), services can have different lifetimes depending on how long their instances are kept. Choosing the right lifetime is important for performance and managing state.

    1. Transient

    A Transient service is created **every time it is requested**. Use it for lightweight, stateless services. 

    // Register service
services.AddTransient<IGreetingService, GreetingService>();

// Service implementation
public class GreetingService : IGreetingService
{
    public Guid Id { get; } = Guid.NewGuid();
    public string Greet() => $"Hello! Service ID: {Id}";
}

    2. Scoped

    A Scoped service is created **once per request**. All components within the same HTTP request share the same instance. 

    // Register service
services.AddScoped<IGreetingService, GreetingService>();

    3. Singleton

    A Singleton service is created **once for the entire application** and shared across all requests. 

    // Register service
services.AddSingleton<IGreetingService, GreetingService>();

    Example Usage in a Controller

    public class HomeController : Controller
{
    private readonly IGreetingService _service;

    public HomeController(IGreetingService service)
    {
        _service = service;
    }

    public IActionResult Index()
    {
        return Content(_service.Greet());
    }
}

    Summary

    • Transient: New instance every injection.
    • Scoped: One instance per HTTP request.
    • Singleton: One instance for the entire application.
    Lifetime Meaning Real-world Examples
    Singleton One instance for the whole app
    • ConfigurationService – app settings
    • LoggingService – centralized logging
    • CacheService – memory cache
    • TelemetryService – analytics
    • EmailSenderService – SMTP client shared across app
    Scoped One instance per request (good for web APIs)
    • UserService – current user context
    • OrderService – handles order per request
    • ShoppingCartService – tracks items per session
    • ClaimService – processes insurance claim per request
    • PaymentService – validates and processes payment per request
    Transient New instance every time it’s requested
    • RandomNumberService
    • EmailTemplateService – lightweight, stateless
    • NotificationBuilder – build notifications dynamically
    • ReportGeneratorService
    • ParserService – parses input per call

    Generics

    Generics allow you to define classes, methods, or interfaces with a placeholder for the type they store or use. This enables type safety, code reuse, and avoids boxing/unboxing for value types.

    Why use Generics?

    • Type safety at compile time
    • Code reuse for multiple types
    • Improved performance by avoiding casting or boxing

    Example: Generic Class

    public class Repository<T>
{
    private List<T> items = new List<T>();

    public void Add(T item)
    {
        items.Add(item);
    }

    public T Get(int index)
    {
        return items[index];
    }
}

// Usage
var intRepo = new Repository<int>();
intRepo.Add(42);
Console.WriteLine(intRepo.Get(0)); // Output: 42

var stringRepo = new Repository<string>();
stringRepo.Add("Hello");
Console.WriteLine(stringRepo.Get(0)); // Output: Hello

    Example: Generic Method

    public void Swap<T>(ref T a, ref T b)
{
    T temp = a;
    a = b;
    b = temp;
}

// Usage
int x = 1, y = 2;
Swap(ref x, ref y);
Console.WriteLine($"{x}, {y}"); // Output: 2, 1

    Summary

    • Generics allow type-agnostic code that is safe and reusable.
    • They work for classes, methods, interfaces, and delegates.
    • Helps avoid runtime errors by catching type issues at compile time.

    LINQ

    LINQ (Language Integrated Query) is a feature in C# that allows you to query collections (arrays, lists, databases, etc.) in a concise and readable way using SQL-like syntax or method chains.

    Why use LINQ?

    • Simplifies querying collections
    • Readable and maintainable code
    • Supports filtering, ordering, grouping, and projection

    Example 1: LINQ with Arrays

    using System;
using System.Linq;

int[] numbers = { 1, 2, 3, 4, 5, 6 };

// Query even numbers
var evens = numbers.Where(n => n % 2 == 0);

foreach (var n in evens)
{
    Console.WriteLine(n); // Output: 2, 4, 6
}

    Example 2: LINQ with Objects

    using System;
using System.Collections.Generic;
using System.Linq;

public class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}

List<Person> people = new List<Person>
{
    new Person { Name = "Alice", Age = 25 },
    new Person { Name = "Bob", Age = 30 },
    new Person { Name = "Charlie", Age = 20 }
};

// Get names of people older than 20
var result = people.Where(p => p.Age > 20).Select(p => p.Name);

foreach (var name in result)
{
    Console.WriteLine(name); // Output: Alice, Bob
}

    Example 3: LINQ Query Syntax vs Method Syntax

    // Method Syntax
var adults = people.Where(p => p.Age >= 21).Select(p => p.Name);

// Query Syntax
var adultsQuery = from p in people
                  where p.Age >= 21
                  select p.Name;

    Summary

    • LINQ makes querying collections simple and expressive.
    • Supports both method syntax and query syntax.
    • Useful for filtering, selecting, ordering, and grouping data.

    IEnumerable vs IQueryable

    Both IEnumerable and IQueryable are used to work with collections in C#, but they differ in **where and how the query is executed**.

    IEnumerable<T>

    • Used for in-memory collections like arrays, lists, etc.
    • Query execution happens in memory (client-side).
    • Supports forward-only iteration.

    Example:

    List<int> numbers = new List<int> { 1, 2, 3, 4, 5 };

// IEnumerable example
IEnumerable<int> evenNumbers = numbers.Where(n => n % 2 == 0);

foreach (var n in evenNumbers)
{
    Console.WriteLine(n); // Output: 2, 4
}

    IQueryable<T>

    • Used for querying external data sources like databases (Entity Framework).
    • Query execution happens on the server, fetching only required data.
    • Supports building dynamic queries with deferred execution.

    Example:

    using (var context = new AppDbContext())
{
    IQueryable<Person> adults = context.People.Where(p => p.Age >= 21);

    foreach (var person in adults)
    {
        Console.WriteLine(person.Name);
    }
}
// The database executes the query; only filtered results are returned.

    Key Differences

    • Execution: IEnumerable - in memory; IQueryable - server-side.
    • Data Source: IEnumerable - in-memory collections; IQueryable - external sources (DB).
    • Performance: IQueryable is more efficient for large datasets because filtering happens on the server.

    CORS (Cross-Origin Resource Sharing)

    CORS is a security feature in web browsers that controls how resources on your server can be accessed by web pages from different origins (domains). It is mainly used in **web API / client-server architecture** to allow or restrict access from external domains.

    Why use CORS?

    • Enables secure cross-domain requests
    • Prevents unauthorized access to your API

    Example: Enabling CORS in ASP.NET Core

    // Program.cs
var builder = WebApplication.CreateBuilder(args);
var MyAllowSpecificOrigins = "_myAllowSpecificOrigins";

builder.Services.AddCors(options =>
{
    options.AddPolicy(name: MyAllowSpecificOrigins,
                      policy =>
                      {
                          policy.WithOrigins("https://example.com")
                                .AllowAnyHeader()
                                .AllowAnyMethod();
                      });
});

var app = builder.Build();

app.UseCors(MyAllowSpecificOrigins);

app.MapControllers();

app.Run();

    Explanation:

    • In a client-server architecture, CORS allows specific front-end domains to call your back-end API safely.
    • It prevents unauthorized websites from making requests to your API.

    MediatR

    MediatR is a .NET library implementing the **Mediator pattern**. It is used in **Clean Architecture / CQRS (Command-Query Responsibility Segregation)** to decouple request handling from request sending. This helps keep your code modular, testable, and reduces direct dependencies between components.

    Why use MediatR?

    • Decouples request senders and handlers
    • Makes the application more maintainable and testable
    • Useful for implementing CQRS pattern (separating commands and queries)

    Example: Using MediatR

    // Install-Package MediatR
using MediatR;

// Define a request (command)
public record CreateUserCommand(string Name, string Email) : IRequest<bool>;

// Define a handler
public class CreateUserHandler : IRequestHandler<CreateUserCommand, bool>
{
    public Task<bool> Handle(CreateUserCommand request, CancellationToken cancellationToken)
    {
        Console.WriteLine($"Creating user: {request.Name}, {request.Email}");
        return Task.FromResult(true);
    }
}

// Usage in Controller
public class UsersController : ControllerBase
{
    private readonly IMediator _mediator;

    public UsersController(IMediator mediator)
    {
        _mediator = mediator;
    }

    [HttpPost("create")]
    public async Task<IActionResult> CreateUser([FromBody] CreateUserCommand command)
    {
        var result = await _mediator.Send(command);
        return Ok(result);
    }
}

    Explanation:

    • The controller sends a request via _mediator.Send() instead of directly calling a service.
    • The handler receives the request and executes business logic.
    • This is commonly used in **Clean Architecture** to separate controllers, business logic, and infrastructure.

    Clean Architecture

    Clean Architecture is a software design approach that separates an application into distinct layers to improve maintainability, testability, and flexibility. It enforces a rule: **inner layers should not depend on outer layers**, but outer layers can depend on inner layers.

    Layers in Clean Architecture

    • Entities / Domain: Core business models and rules (no dependencies on other layers).
    • Use Cases / Application: Business logic, commands, and queries. Depends only on Entities.
    • Interface / Web / API: Controllers, API endpoints, UI. Depends on Application layer.
    • Infrastructure: Database, external services, repositories. Implements interfaces from Application layer.

    Benefits

    • Independent of frameworks and UI.
    • Easier to test.
    • Supports multiple front-ends (web, desktop, mobile) with the same core logic.

    Typical File Structure

    MyProject/
│
├── MyProject.Domain/          # Entities, domain models
│   └── Person.cs
│
├── MyProject.Application/     # Use cases, commands, queries, interfaces
│   ├── Interfaces/
│   │   └── IUserRepository.cs
│   └── Services/
│       └── UserService.cs
│
├── MyProject.Infrastructure/  # Database, external APIs, repository implementations
│   └── Repositories/
│       └── UserRepository.cs
│
├── MyProject.API/             # Controllers, API endpoints
│   └── Controllers/
│       └── UsersController.cs
│
└── MyProject.Tests/           # Unit and integration tests
    └── UserServiceTests.cs

    How It Works

    • Controllers in API layer call services in Application layer.
    • Application layer calls domain entities and interfaces.
    • Infrastructure layer implements these interfaces (e.g., database access).
    • Inner layers never depend on outer layers; dependencies point inward.

    Extension Method

    Extension Methods allow you to add new methods to existing types (classes, interfaces, structs) without modifying their source code or creating a new derived type. They are commonly used for utility methods, helper functions, and LINQ.

    How to Define an Extension Method

    • Must be defined in a static class.
    • The method itself must be static.
    • The first parameter specifies the type being extended and must be prefixed with this.

    Example: String Extension

    using System;

public static class StringExtensions
{
    // Extension method to capitalize the first letter of a string
    public static string CapitalizeFirstLetter(this string str)
    {
        if (string.IsNullOrEmpty(str))
            return str;

        return char.ToUpper(str[0]) + str.Substring(1);
    }
}

// Usage
class Program
{
    static void Main()
    {
        string name = "eric";
        string capitalized = name.CapitalizeFirstLetter();
        Console.WriteLine(capitalized); // Output: Eric
    }
}

    Key Points

    • You can call the extension method as if it were a method of the type itself.
    • Works with both built-in types (like string) and custom classes.
    • Helps keep utility methods organized without cluttering the original class.

    Optimize Memory in .NET

    Memory optimization in .NET is about managing how your application allocates, uses, and releases memory to improve performance and reduce memory-related issues like leaks or excessive garbage collection.

    Key Techniques:

    • Use value types wisely: Value types (structs) are stored on the stack and reduce heap allocations compared to reference types.
    • Dispose objects properly: Implement IDisposable and use using statements for objects holding unmanaged resources (e.g., file handles, database connections).
    • String optimization: Use StringBuilder for repeated string concatenation instead of using + operator.
    • Use memory-efficient collections: Choose Span<T>, Memory<T>, or ArrayPool<T> for large datasets.
    • Minimize large object heap (LOH) fragmentation: Avoid creating many large objects repeatedly; reuse buffers when possible.

    Example: Using StringBuilder

    using System;
using System.Text;

class Program
{
    static void Main()
    {
        StringBuilder sb = new StringBuilder();

        for (int i = 0; i < 1000; i++)
        {
            sb.Append("Line " + i + Environment.NewLine);
        }

        string result = sb.ToString();
        Console.WriteLine(result.Substring(0, 50) + "...");
    }
}

    Example: Properly disposing objects

    using (var file = new System.IO.StreamWriter("log.txt"))
{
    file.WriteLine("Log entry");
} // StreamWriter automatically disposed here

    Summary

    • Reduce unnecessary heap allocations.
    • Dispose unmanaged resources promptly.
    • Use memory-efficient types and collections.
    • Consider performance profiling to identify memory hotspots.

    Stack vs Heap

    In .NET, memory is managed in two main areas: the stack and the heap. Understanding the difference helps write more efficient and performant code.

    Stack

    • Stores value types (like int, bool, struct) and references to objects.
    • Memory is automatically managed with a Last-In-First-Out (LIFO) structure.
    • Fast allocation and deallocation.
    • Limited size; suitable for small, short-lived data.

    Example:

    int a = 10;   // 'a' stored on the stack
int b = 20;   // 'b' stored on the stack
int sum = a + b;
Console.WriteLine(sum); // Output: 30

    Heap

    • Stores reference types (like class objects) and large objects.
    • Memory is managed by the garbage collector (GC) in .NET.
    • Slower allocation and deallocation compared to stack.
    • Suitable for objects that live longer or need to be shared.

    Example:

    class Person
{
    public string Name { get; set; }
}

Person p = new Person(); // Object allocated on the heap
p.Name = "Eric";
Console.WriteLine(p.Name); // Output: Eric

    Key Differences

    Feature Stack Heap
    Data Stored Value types, references Reference type objects
    Lifetime Short-lived, automatic Managed by GC, longer-lived
    Access Speed Fast Slower
    Size Limited Large

    Garbage Collector

    The Garbage Collector (GC) in .NET automatically manages memory by reclaiming memory occupied by objects that are no longer in use. This helps prevent memory leaks and reduces the need for manual memory management.

    How it works:

    • Allocates memory for objects on the heap.
    • Tracks which objects are still in use and which are no longer referenced.
    • Automatically frees memory for objects that are unreachable.
    • Runs periodically in the background to optimize performance.

    Example:

    class Program
{
    static void Main()
    {
        // Create a new object
        Person p = new Person();
        p.Name = "Eric";

        // After this block, 'p' goes out of scope and can be collected by GC
    }
}

class Person
{
    public string Name { get; set; }
}

    Key Points:

    • Developers do not need to manually free memory for managed objects.
    • For unmanaged resources (like file handles, database connections), always implement IDisposable and use using.
    • Excessive object creation can trigger frequent GC runs, affecting performance.
    • Understanding GC generations (0, 1, 2) can help optimize memory usage for long-lived objects.
