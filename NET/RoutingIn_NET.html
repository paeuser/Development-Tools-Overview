Routing in .NET — Explained

A concise guide with examples for ASP.NET Core (conventional, attribute, and Minimal API routing). Works with .NET 6, 7, 8 and later.

What is routing?

Routing maps incoming HTTP requests (URL + verb) to code that handles them (controllers, actions, or minimal API delegates).

  • Path matching: which URL pattern should trigger which handler.
  • Verb matching: GET, POST, PUT, DELETE, etc.
  • Parameter binding: extract values from the path, query string, headers, or body.

Classic pipeline (Startup/Program)

In modern ASP.NET Core the order is important. Typical setup (Program.cs):

// Program.cs (minimal template)
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();

var app = builder.Build();

app.UseRouting();              // sets up routing middleware
app.UseAuthorization();       // optional

app.MapControllers();         // map controller endpoints
app.Run();

In older templates you might see UseEndpoints(endpoints => { endpoints.MapControllers(); }). Under the hood that's endpoint routing.

Conventional routing (MVC-style)

Define patterns that controllers follow. Typical default route:

// inside Program.cs or UseEndpoints
app.MapControllerRoute(
  name: "default",
  pattern: "{controller=Home}/{action=Index}/{id?}");

Examples:

/Products/Details/5 → ProductsController.Details(int id)
/ → HomeController.Index() (because of defaults)

Attribute routing

Decorate controllers and actions with routes — gives fine-grained control and is common in APIs.

[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult GetAll() => Ok(...);

    [HttpGet("{id:int}")]
    public IActionResult GetById(int id) => Ok(...);

    [HttpPost]
    public IActionResult Create(Product p) => CreatedAtAction(nameof(GetById), new { id = p.Id }, p);
}

Route tokens: [controller], [action]. Constraints like :int, :guid, :alpha help ensure proper matching.

Minimal APIs (MapGet / MapPost)

Introduced in .NET 6 — create lightweight endpoints without controllers.

// Program.cs
var app = WebApplication.CreateBuilder(args).Build();

app.MapGet("/hello", () => "Hello world!");
app.MapGet("/orders/{id:int}", (int id) => $"Order {id}");

app.Run();

You can also add filters, minimal DI, and produce OpenAPI docs with builder.Services.AddEndpointsApiExplorer().

Route parameters & special patterns

  • Optional parameter: {id?}
  • Default value: {page=1}
  • Catch-all: {*slug} captures the rest of the path (including slashes)
  • Constraints: {id:int}, {guid:guid}, {name:alpha}
// examples
app.MapControllerRoute("blog",
  "blog/{year:int}/{month:int}/{slug}",
  new { controller = "Blog", action = "Post" });

Route precedence & matching

Routing chooses the first endpoint that matches. Be careful with broad catch-all routes; register more-specific routes before broader ones.

  • Attribute routes are considered before convention routes when mapping controllers.
  • When using MapGet/MapPost, the order you call them in Program.cs matters for ambiguous paths.

Link generation

Routing is reversible — you can generate URLs from route names or action/controller names:

// inside a controller
var url = Url.Action("Details", "Products", new { id = 5 });

// with endpoints & minimal APIs you can name routes:
app.MapGet("/users/{id}", GetUser).WithName("GetUserById");
// later
var urlHelper = app.Services.GetRequiredService();
var link = urlHelper.GetPathByName("GetUserById", new { id = 42 });

Common pitfalls & tips

  • Missing app.UseRouting() or calling UseEndpoints before authentication/authorization can break route-based policies.
  • Route constraints are matched after splitting — if you expect a GUID, use :guid to avoid model-binding errors.
  • Be careful with overlapping routes — prefer specific patterns first.
  • Use app.MapFallback for SPA fallback (serve index.html for unknown routes).

Quick reference: Examples in one place

// Attribute routing (Controller)
[Route("api/[controller]")]
public class PeopleController : ControllerBase
{
    [HttpGet]
    public IActionResult List() => Ok();

    [HttpGet("{id:int}")]
    public IActionResult Get(int id) => Ok();
}

// Conventional route
app.MapControllerRoute("default", "{controller=Home}/{action=Index}/{id?}");

// Minimal API
app.MapGet("/products/{id:int}", (int id) => Results.Ok(new { id }));
