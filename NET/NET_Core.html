.NET Core / ASP.NET Core General

1. What is CORS in .NET?

CORS (Cross-Origin Resource Sharing) is a browser security feature that controls which websites (origins) can make requests to your web API or server. By default, browsers block cross-origin requests. CORS allows the server to explicitly permit specific origins. How it works: - Origin: Protocol + domain + port (e.g., https://example.com:443). - Preflight request: Browsers send an OPTIONS request for certain HTTP methods (PUT, DELETE) or custom headers. - CORS headers: Server responds with headers like: - Access-Control-Allow-Origin → allowed domains - Access-Control-Allow-Methods → allowed HTTP methods - Access-Control-Allow-Headers → allowed headers CORS in .NET Core / .NET 5+ example: 
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowSpecificOrigin",
        builder => builder
            .WithOrigins("https://example.com")
            .AllowAnyMethod()
            .AllowAnyHeader());
});
app.UseCors("AllowSpecificOrigin");
CORS in ASP.NET Web API (Framework): 
using System.Web.Http.Cors;

var cors = new EnableCorsAttribute("https://example.com", "*", "*");
config.EnableCors(cors);

[EnableCors(origins: "https://example.com", headers: "*", methods: "*")]
public class MyApiController : ApiController { }
Key points: - CORS is enforced by browsers, not the server. - Limit allowed origins in production for security. - Preflight OPTIONS requests are handled automatically by the middleware.

7. What is the difference between AddSingleton, AddScoped, and AddTransient?

AddSingleton: A single instance is created and shared for the entire application lifetime. Examples:

  • services.AddSingleton<ILoggingService, LoggingService>();
  • services.AddSingleton<IConfigurationService, ConfigurationService>();
  • services.AddSingleton<ICacheService, MemoryCacheService>();

AddScoped: A new instance is created once per HTTP request. Within the same request, all usages share the same instance. Examples:

  • services.AddScoped<IUserService, UserService>();
  • services.AddScoped<IOrderService, OrderService>();
  • services.AddScoped<IDbContext, ApplicationDbContext>();

AddTransient: A new instance is created every time the service is requested. Even within the same HTTP request, multiple injections will produce different objects. Examples:

  • services.AddTransient<IEmailService, EmailService>();
  • services.AddTransient<INotificationService, NotificationService>();
  • services.AddTransient<IReportGenerator, ReportGenerator>();

Summary:

  • Singleton: One for the whole app (best for logging, caching, configuration).
  • Scoped: One per request (best for database contexts, user/session data).
  • Transient: Always new (best for lightweight, stateless operations like sending emails).

1. What is the difference between .NET Framework and .NET Core?

.NET Framework is Windows-only and mature, while .NET Core is cross-platform, open-source, and modular for modern cloud and microservices apps.

2. What are the main benefits of ASP.NET Core over ASP.NET MVC 5?

ASP.NET Core is cross-platform, faster, has built-in dependency injection, better modularity via middleware, and supports side-by-side versioning.

3. What are middleware components in ASP.NET Core, and how are they configured?

Middleware are software components forming a pipeline to handle HTTP requests/responses. Configured in Startup.cs using IApplicationBuilder's Use methods.

4. Explain the difference between IApplicationBuilder and IServiceCollection.

IServiceCollection registers services for dependency injection. IApplicationBuilder configures middleware components in the HTTP request pipeline.

5. What is dependency injection, and how is it implemented in ASP.NET Core?

DI is a pattern that provides objects their dependencies instead of creating them. ASP.NET Core has built-in DI container configured via IServiceCollection.

6. How do you configure app settings across environments (e.g., dev, staging, prod)?

Using appsettings.json files (e.g., appsettings.Development.json) combined with environment variables and IConfiguration to load settings per environment.

8. How does model binding work in ASP.NET Core MVC?

It maps HTTP request data (query, route, form, body) to action method parameters or model properties automatically.

9. How do you handle validation in a Web API controller?

Using data annotations on models, then checking ModelState.IsValid in controller actions to return 400 Bad Request on validation failure.

10. What’s the role of Startup.cs in ASP.NET Core apps?

Startup.cs configures services (DI) and the HTTP request pipeline (middleware) for the app.

Web API & REST

11. How do you build a RESTful Web API in ASP.NET Core?

By creating controllers deriving from ControllerBase, using routing, returning IActionResult, and following REST conventions with HTTP verbs.

12. How do you version a Web API?

Using URL segments (e.g., /api/v1/), query strings, headers, or Microsoft.AspNetCore.Mvc.Versioning package.

13. How do you return custom HTTP responses or error codes?

Using IActionResult return types like BadRequest(), NotFound(), Created(), or custom ObjectResult with status codes.

14. What is the difference between [FromBody], [FromQuery], and [FromRoute]?

They specify where the parameter value comes from: body payload, query string, or route URL segment respectively.

15. How do you implement authentication/authorization in ASP.NET Core Web APIs?

Configure authentication schemes (JWT, OAuth), add [Authorize] attribute, and configure policies and middleware.

16. What are filters (e.g., action, result, exception) in Web APIs?

Filters are components to run code before/after controller actions for cross-cutting concerns like logging, authorization, and error handling.

17. How do you handle global exception handling in ASP.NET Core?

Using middleware like UseExceptionHandler or custom middleware to catch and respond to unhandled exceptions globally.

18. How do you implement pagination in a RESTful API?

Using query params for page size and number, returning paged results with metadata like total count and links.

19. How do you protect APIs using OAuth 2.0 or OpenID Connect?

By validating access tokens issued by identity providers on each request and enforcing scopes/claims.

20. How would you implement API rate limiting?

Using middleware or third-party libraries to limit requests per IP/user over a time window.

.NET Security

21. How do you implement JWT authentication in ASP.NET Core?

Configure JwtBearer authentication in Startup.cs, validate tokens in middleware, and protect routes using [Authorize].

22. What are data protection APIs in ASP.NET Core?

APIs to encrypt/decrypt sensitive data like cookies or tokens, ensuring security at rest and in transit.

23. How do you prevent CSRF and XSS in a .NET web app?

Use anti-forgery tokens for CSRF; encode output and validate input to prevent XSS.

24. How would you handle secrets in .NET apps in production?

Use Azure Key Vault, AWS Secrets Manager, environment variables, or user secrets in development.

25. What is the purpose of HTTPS and how to enforce it in ASP.NET Core?

HTTPS encrypts data in transit. Use UseHttpsRedirection middleware and HSTS headers.

Databases & ORM

26. What is Entity Framework Core?

EF Core is a lightweight, cross-platform ORM for .NET to work with databases using LINQ and models.

27. Explain Code First vs Database First approaches.

Code First: Create models then generate DB. Database First: Use existing DB to generate models.

28. How do you configure migrations in EF Core?

Using CLI commands like dotnet ef migrations add and dotnet ef database update.

29. How do you improve performance of EF Core queries?

Use eager loading, compiled queries, no-tracking queries, and optimize LINQ expressions.

30. How do you handle concurrency conflicts in EF Core?

Use concurrency tokens with [Timestamp] attribute and handle DbUpdateConcurrencyException.

Microservices & Architecture

31. What are microservices, and how do they differ from monolithic apps?

Microservices are small, independent services communicating over APIs. Monoliths are a single unified app.

32. How do you build and deploy microservices using .NET Core?

Develop separate .NET Core apps, containerize with Docker, orchestrate with Kubernetes, and use REST/gRPC for communication.

33. What is the role of API Gateway in microservices?

Acts as a single entry point, routing requests, handling auth, throttling, and aggregating responses.

34. Explain CQRS and event sourcing concepts.

CQRS separates read/write models; event sourcing persists state changes as events.

35. What are common patterns to ensure data consistency across microservices?

Use eventual consistency, distributed transactions (sagas), or message queues.

Testing & CI/CD

36. How do you unit test ASP.NET Core controllers?

Using xUnit or NUnit with mocks for dependencies to isolate controller logic.

37. What are integration tests and how do they differ from unit tests?

Integration tests check multiple components working together, while unit tests isolate single units.

38. How do you mock dependencies in .NET tests?

Using mocking frameworks like Moq or NSubstitute to create fake implementations.

39. How do you implement continuous integration and deployment for .NET apps?

Use Azure DevOps, GitHub Actions, or Jenkins pipelines to build, test, and deploy automatically on commits.

40. How do you measure code coverage in .NET?

Using tools like Coverlet integrated with test runners and reporting coverage in CI.

Advanced Topics

41. What is async/await in C# and why is it important?

Allows asynchronous programming without blocking threads, improving scalability and responsiveness.

42. What are Span<T> and Memory<T> in .NET?

They are structs for efficient memory handling and slicing without allocations.

43. What is the difference between Task and Thread?

Task is an abstraction for asynchronous work; Thread is an OS-level thread.

44. Explain the IDisposable interface and when to use it.

IDisposable allows releasing unmanaged resources deterministically with Dispose method.

45. What is reflection and how is it used?

Reflection lets you inspect and manipulate metadata and types at runtime.

46. What are extension methods?

Static methods that add functionality to existing types without inheritance.

47. How do you handle configuration in .NET Core apps?

Using IConfiguration with appsettings.json, environment variables, and custom providers.

48. What is the difference between synchronous and asynchronous streams?

Synchronous streams yield values synchronously; asynchronous streams use async enumeration (IAsyncEnumerable).

49. How do you optimize memory usage in .NET applications?

Avoid unnecessary allocations, use structs/Span, dispose resources, and profile memory.

50. What is a garbage collector and how does it work?

Automatically frees unused managed memory via generational collection to improve app performance.
