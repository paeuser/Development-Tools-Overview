What Happens When You Refresh a SPA

Refreshing a Single Page Application (SPA) reloads the JavaScript context, which affects state differently depending on how it is stored:

State Type Behavior on Refresh
In-Memory State (JS Variables, Redux, Vuex) Lost on refresh because the JavaScript memory is reset.
SessionStorage Persists across refresh in the same tab. Cleared if the tab is closed.
LocalStorage Persists even after refresh or closing/reopening the browser.
Cookies Persist based on expiration settings. Refresh does not clear them.
Token-based Authentication (JWT) If stored in memory, lost on refresh. If stored in localStorage or cookies, it remains.

Summary: Refreshing a SPA resets in-memory state. Persistent storage mechanisms like sessionStorage, localStorage, and cookies survive the refresh according to their rules.

10 Tricky SPA/State Management Interview Questions

Question Answer
What happens to Redux state if the page is refreshed? Redux state stored in memory is lost on refresh unless persisted to localStorage or sessionStorage.
Can you rely solely on localStorage for storing sensitive user tokens? No, localStorage is vulnerable to XSS attacks; HTTP-only cookies are safer for sensitive data.
What is the difference between sessionStorage and localStorage? sessionStorage persists only for the tab session, while localStorage persists across browser sessions.
Why SPAs are considered stateless on the server? SPAs maintain state on the client-side; the server does not retain session info unless explicitly managed.
How can you persist in-memory state across page refresh? By saving it to localStorage, sessionStorage, or a backend server and rehydrating on load.
What is the risk of storing JWT in localStorage? XSS attacks can access the token since it is readable by JavaScript.
If a user opens the SPA in a new tab, what happens to sessionStorage? SessionStorage is not shared across tabs; a new tab starts with empty sessionStorage.
How would you handle token expiration in a SPA? Implement a refresh token mechanism or force re-login when the token expires.
Can cookies be used to share state between server and SPA? Yes, HTTP-only cookies can store session info accessible by the server but not JavaScript.
What is the difference between in-memory state and state managed by Redux or Vuex? In-memory state can be any JS variable; Redux/Vuex provides a centralized, structured, and predictable way to manage state.

SPA Refresh and State Handling

Handling User Refresh in a SPA

When a user refreshes a Single Page Application, the JavaScript context is reloaded and in-memory state is lost. To handle this, persistent storage or server-side session can be used.

1. Persist State in LocalStorage or SessionStorage

// Save state
localStorage.setItem('user', JSON.stringify({ name: 'Eric', token: 'abc123' }));


// Restore state on page load
const user = JSON.parse(localStorage.getItem('user'));
if (user) {
console.log('Welcome back,', user.name);
}

2. Use Cookies for Authentication

Store authentication tokens securely in HTTP-only cookies that persist across refreshes.

3. Token Rehydration on Load

const token = localStorage.getItem('accessToken');
if (token) {
fetch('/api/user', {
headers: { 'Authorization': 'Bearer ' + token }
})
.then(res => res.json())
.then(userData => console.log('User restored:', userData));
}

4. Server-Side Session

Minimal client state can be stored while the server manages the session. On refresh, the client queries the server using a session ID stored in a cookie to restore state.

Summary: Persist critical state in localStorage, sessionStorage, or cookies, and rehydrate it after a refresh to maintain the user's session and data.
