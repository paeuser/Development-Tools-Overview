Reduce Angular Bundle Size — Practical Guide

Concrete steps, code examples and commands you can run today to shrink your app and speed up load/parse times.
Performance

Quick checklist

  • Enable production build & AOT
  • Use lazy-loaded modules for routes and large features
  • Remove unused libraries and prefer small utilities: Run npx depcheck to find unused dependencies and uninstall them. Replace heavy libraries (e.g., moment → date-fns / dayjs, lodash → individual function imports or native JS). Avoid import * or barrel imports — always import only what you use so Angular’s tree-shaking can remove the rest. Add depcheck as an npm script to automate regular checks and keep dependencies lean.
  • Use tree-shaking-friendly imports: Import only what you need (e.g., import debounce from 'lodash/debounce') instead of wildcard imports (e.g., import * as _ from 'lodash'). This lets Angular remove unused code and keep bundles smaller.
  • Bundle-analyze and iterate
  • Serve compressed assets (gzip / brotli) and enable caching

1) Build for production (AOT, optimizations)

Always produce a production build before measuring. This enables AOT, minification, and optimization.

// Angular CLI common commands
ng build --configuration production
// or (older shorthand)
ng build --prod
Tip: Turn off source-maps in production to reduce artifact size: 
"configurations": {
  "production": {
    "sourceMap": false,
    "optimization": true,
    "aot": true
  }
}

2) Lazy-load feature modules (routes)

Move big features into modules and lazy-load via the router so initial bundle only contains shell + essentials.

// app-routing.module.ts (Angular v9+)
const routes: Routes = [
  { path: '', component: HomeComponent },
  { 
    path: 'admin', 
    loadChildren: () => import('./admin/admin.module').then(m => m.AdminModule) 
  },
  // ...
];

In AdminModule, declare the admin components. Only loaded when user navigates to /admin.

3) Prefer component-level imports and tree-shakable libraries

Avoid importing whole libraries when you only need parts.

// bad - brings whole library
import * as _ from 'lodash';

// good - only bring the helper you need
import debounce from 'lodash/debounce';
Tip: For UI libraries, import only used components or use on-demand component imports (or switch to a smaller UI kit).

4) Remove polyfills and large dependencies you don't need

🔎 What are Polyfills? A polyfill is a piece of code (usually JS) that adds support for features that some browsers don’t have natively. Example: Internet Explorer (IE11) didn’t support Promise, so Angular included a Promise polyfill.

Check polyfills.ts. Modern browsers may not need many polyfills. Only include what your supported browsers require.

// src/polyfills.ts
// comment-out polyfills you don't need (only after verifying browser support)

5) Use lazy images & avoid shipping large assets

  • Use <img loading="lazy"> for off-screen images.
  • Move very large images to a CDN or serve scaled/optimized WebP images.

6) Analyze the bundle → find the heavy parts

Find which files or libraries are largest and focus efforts there.

// 1) generate production build with source maps
ng build --configuration production --source-map=true

// 2) analyze (example tools)
npx source-map-explorer dist/my-app/main.*.js
// OR
npx webpack-bundle-analyzer dist/my-app/stats.json
Focus on the top 3 offenders — removing or replacing one big library often yields the largest wins.

7) Code-splitting beyond routes

Use dynamic imports for rarely used utilities or heavy third-party features:

async function openEditor() {
  const { EditorModule } = await import('./editor/editor.module');
  // programmatically load or bootstrap the editor module
}

8) Avoid shipping large polyfill bundles & locales

If you use libraries that include many locales (e.g., date libraries), import only required locales or use Intl APIs.

// moment.js example - DON'T import all locales
import moment from 'moment';            // heavy
// Prefer:
import { format, parseISO } from 'date-fns'; // tree-shakable & smaller

9) Enable compression & caching on the server

Compression reduces transfer size dramatically. Configure your production server or CDN to serve pre-compressed assets (brotli/gzip) and add long-cache headers.

// nginx example (brief)
gzip on;
gzip_types text/css application/javascript application/json;
# better: generate brotli files and serve with proper headers (CDN recommended)

10) Misc practical tips

Disable dev tools & zone checks

Ensure production build removes dev-only checks. Angular CLI does this automatically in prod but verify: enableProdMode() is used if you bootstrap manually.

Turn off source maps in prod

Source maps increase artifact size — set sourceMap: false for prod builds in angular.json.

Smaller RxJS

Import operators directly: import { map } from 'rxjs/operators' and rely on tree-shaking. Avoid deep imports that accidentally pull in entire RxJS bundles.

Sample package.json scripts

{
  "scripts": {
    "build:prod": "ng build --configuration production",
    "analyze": "npx source-map-explorer \"dist/my-app/*.js\"",
    "build:prod:stats": "ng build --configuration production --stats-json && npx webpack-bundle-analyzer dist/my-app/stats.json"
  }
}

Common pitfalls and how to check for them

  • Large vendor bundle: run the analyzer → if vendor chunk large, inspect which dependencies dominate.
  • Duplicate libraries: two libraries doing same job (e.g., moment + date-fns). Consolidate.
  • Big polyfills or dev-only imports: check your main.ts and polyfills.ts for unintended imports.

Where to focus first (practical prioritization)

  1. Measure with analyzer (get facts).
  2. Lazy-load features & routes.
  3. Replace or refactor any library that is the largest single weight.
  4. Enable compression & caching on server/CDN.
