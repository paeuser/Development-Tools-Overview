Angular

Angular is a platform and framework for building single-page web applications using TypeScript and HTML. It allows you to create dynamic and interactive web apps with reusable components.

})

CLI stands for Command-Line Interface. The Angular CLI is a tool that helps you create, manage, and build Angular projects quickly from the command line.

AppComponent

AppComponent is the root component of an Angular application. Every Angular app has at least one root component, which is usually AppComponent.

Simple Example:

@Component({
  selector: 'app-root',

  `
})
//makes this class available outside of this file.
export class AppComponent { }

The selector: 'app-root' allows you to place this component in index.html like this: <app-root></app-root>

AppModule

AppModule is the root module of an Angular application. It organizes the app by telling Angular which components to use, which modules to import, and which component to start with.

Simple Example with Explanations:


import { NgModule } from '@angular/core';           // Import NgModule decorator
import { BrowserModule } from '@angular/platform-browser'; // Needed to run the app in a browser
import { AppComponent } from './app.component';     // Import the root component

@NgModule({
  declarations: [
    AppComponent  // Declare all components, directives, and pipes that belong to this module
  ],
  imports: [
    BrowserModule // Import other modules that your app depends on
  ],
  providers: [
    // Add services here if needed, e.g., data services
  ],
  bootstrap: [
    AppComponent // Define the root component to load first when the app starts
  ]
})
export class AppModule { } // Export the module so Angular can use it

Explanation of sections:

  • declarations: Lists components, directives, and pipes used in this module.
  • imports: Lists other modules this module depends on.
  • providers: Registers services for dependency injection.
  • bootstrap: Tells Angular which component to load first.

In newer versions of Angular, you can still use AppModule to organize your app, but Angular also supports standalone components that can run without a module. AppModule is useful for larger apps or when using multiple modules, while standalone components make smaller apps simpler by reducing boilerplate code.

AppModule Example:

@NgModule({
  declarations: [AppComponent],
  imports: [BrowserModule],
  bootstrap: [AppComponent]
})
export class AppModule { }

Standalone Component Example:

import { bootstrapApplication } from '@angular/platform-browser';
import { AppComponent } from './app/app.component';

bootstrapApplication(AppComponent); // No AppModule needed

Component

A Component is the basic building block of an Angular application. It controls a part of the screen called a view and consists of an HTML template, a TypeScript class, and optional CSS styles.

@Component in Angular is a structural type of directive called a “component directive”

Simple Example:


import { Component } from '@angular/core';

@Component({
  selector: 'app-root',   // Custom HTML tag to use this component
  template: `
    <h1>Hello, Angular Component!</h1>
    <p>This is a simple component.</p>
  `
})
//makes this class available outside of this file.
export class AppComponent { }

Explanation:

  • selector: Defines the HTML tag to use this component.
  • template: HTML code displayed by the component.
  • class: Holds the logic and data for the component.

Component Architecture

Component-based architecture is a design approach where an application is built using small, reusable, and self-contained components. Each component encapsulates its own HTML template, TypeScript logic, and optional CSS styles. Components can communicate with each other via inputs and outputs, allowing for modular, maintainable, and scalable applications.

Simple Example:

  import { Component } from '@angular/core';

@Component({
selector: 'app-parent',
template: <h1>Parent Component</h1> <app-child [message]="'Hello from parent!'"></app-child>
})
export class ParentComponent { }



import { Component, Input } from '@angular/core';

@Component({
selector: 'app-child',
template: <p>{{ message }}</p>
})
export class ChildComponent {
@Input() message!: string;
}

Data Binding

Data binding in Angular is a mechanism to coordinate parts of a template with parts of a component class. It allows you to pass data and listen to events between the component class and its template. Angular provides several types of data binding.

Types of Data Binding:

1. Interpolation ({{ }}) – Component → Template


export class AppComponent {
  title = 'Hello Angular';
}


<h1>{{ title }}</h1>

2. Property Binding ([property]) – Component → Template Property

<input [value]="title">

3. Event Binding ((event)) – Template → Component

<button (click)="onClick()">Click Me</button>

export class AppComponent {
  onClick() {
    alert('Button clicked!');
  }
}

4. Two-way Binding [(ngModel)] – Component ↔ Template (both directions)

<input [(ngModel)]="title">
<p>You typed: {{ title }}</p>

Parent ↔ Child Communication Example

Parent → Child (Input)
How it works In the child component, you declare a property and decorate it with @Input(). In the parent component, you bind a value to that property using property binding syntax: [property]="value". 


import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-child',
  template: '<p>Message from parent: {{ message }}</p>'
})
export class ChildComponent {
  @Input() message!: string;
}


<app-child [message]="parentMessage"></app-child>


export class ParentComponent {
  parentMessage = 'Hello Child!';
}

Child → Parent (Output)


import { Component, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-child',
  template: '<button (click)="sendMessage()">Send to Parent</button>'
})
export class ChildComponent {
  @Output() messageEvent = new EventEmitter<string>();

  sendMessage() {
    this.messageEvent.emit('Hello Parent!');
  }
}


<app-child (messageEvent)="receiveMessage($event)"></app-child>
<p>Message from child: {{ childMessage }}</p>


export class ParentComponent {
  childMessage = '';

  receiveMessage(msg: string) {
    this.childMessage = msg;
  }
}

Two-way binding between parent and child (Input + Output)


import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-child',
  template: '<input [(ngModel)]="childValue" (ngModelChange)="valueChange.emit($event)">'
})
export class ChildComponent {
  @Input() childValue!: string;
  @Output() valueChange = new EventEmitter<string>();
}


<app-child [(childValue)]="parentValue"></app-child>
<p>Parent value: {{ parentValue }}</p>


export class ParentComponent {
  parentValue = 'Initial';
}

This demonstrates all types of data binding, including interpolation, property binding, event binding, and two-way binding, along with communication from parent → child, child → parent, and two-way binding.

@Input()

The @Input() decorator in Angular is used to pass data from a parent component to a child component. It establishes one-way communication from parent → child. 


// child.component.ts
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-child',
  template: `
Message from parent: {{ message }}
`
})
export class ChildComponent {
  @Input() message: string = '';
}

// parent.component.html
<app-child [message]="parentMessage"></app-child>

@Output()

The @Output() decorator in Angular is used to send data or events from a child component back to the parent. It uses EventEmitter for child → parent communication. 


// child.component.ts
import { Component, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-child',
  template: ``
})
export class ChildComponent {
  @Output() messageEvent = new EventEmitter<string>();

  sendMessage() {
    this.messageEvent.emit("Hello from child!");
  }
}

// parent.component.html
<app-child (messageEvent)="receiveMessage($event)"></app-child>
<p>Message from child: {{ childMessage }}</p>

Decorators (@)

In Angular (and TypeScript), the @ symbol is used for decorators. A decorator is a special function that can add metadata or behavior to a class, method, or property. Angular uses decorators like @Component, @Input(), and @Output() to tell the framework how pieces of code should behave. 


// Example of a simple custom decorator
function LogProperty(target: any, propertyKey: string) {
  console.log(`Property "${propertyKey}" has been decorated`);
}

class Example {
  @LogProperty
  name: string = '';
}

In Angular specifically:

  • @Component → defines a component
  • @Input() → receives data from parent
  • @Output() → sends data/events to parent

Dependency Injection

Dependency Injection (DI) in Angular is a design pattern where a class (like a component or service) asks for its dependencies from the framework instead of creating them itself. This makes the code more reusable, testable, and easier to manage. 


// service.ts
import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root'
})
export class LoggerService {
  log(msg: string) {
    console.log('LOG:', msg);
  }
}

// component.ts
import { Component } from '@angular/core';
import { LoggerService } from './service';

@Component({
  selector: 'app-root',
  template: ``
})
export class AppComponent {
  constructor(private logger: LoggerService) {} // injected automatically

  doSomething() {
    this.logger.log('Button was clicked!');
  }
}

In this example:

  • LoggerService is a dependency.
  • Angular's DI system automatically provides it to AppComponent through the constructor.
  • No need to use new LoggerService() — Angular manages it for us.

ng g c components/child

The command ng g c components/child (short for ng generate component components/child) is used to generate a new Angular component called ChildComponent inside the components/child folder.

When you run this command, Angular CLI automatically creates the following files:

  • child.component.ts – The TypeScript class file for the component logic.
  • child.component.html – The HTML template for the component view.
  • child.component.css (or .scss/.sass depending on your setup) – Styles for this component.
  • child.component.spec.ts – A testing file for unit tests of this component.

Additionally, Angular CLI updates the declarations array in the nearest module (usually app.module.ts) to register the new component automatically, so it can be used in templates with the selector <app-child></app-child>.

Directives

Directives in Angular are classes that can modify the behavior, appearance, or structure of DOM elements. They are instructions in the template that Angular interprets to make dynamic changes.

Types of Directives:

1. Component Directives

Components are actually a special type of directive with their own template (HTML view) and optional styles. 


import { Component } from '@angular/core';

@Component({
  selector: 'app-root',
  template: '<h1>Hello, Component Directive!</h1>'
})
export class AppComponent { }

2. Structural Directives

Structural directives change the DOM structure by adding or removing elements. They usually have a * prefix. 


<p *ngIf="isVisible">This paragraph is conditionally visible.</p>


<ul>
  <li *ngFor="let item of items">{{ item }}</li>
</ul>

Structural Directives

Structural directives in Angular change the DOM layout by adding or removing elements. They usually have a * prefix in templates.

1. *ngIf – Conditionally adds or removes an element:

<p *ngIf="isVisible">
  This paragraph is visible only if isVisible is true.
</p>

2. *ngFor – Loops over a collection and renders a template for each item:

<ul>
  <li *ngFor="let item of items">{{ item }}</li>
</ul>

3. *ngSwitch / *ngSwitchCase / *ngSwitchDefault – Conditional switch between elements:

<div [ngSwitch]="color">
  <p *ngSwitchCase="'red'">Red color</p>
  <p *ngSwitchCase="'blue'">Blue color</p>
  <p *ngSwitchDefault>Unknown color</p>
</div>

4. *ngTemplateOutlet – Dynamically render a template:

<ng-template #tpl>
  <p>Hello from template</p>
</ng-template>

<ng-container *ngTemplateOutlet="tpl"></ng-container>

These directives allow you to dynamically control the DOM structure, making your Angular templates flexible and powerful.

3. Attribute Directives

Attribute directives change the appearance or behavior of an element without changing the DOM structure. 


<p [ngStyle]="{'color': textColor, 'font-weight': 'bold'}">Styled text</p>


<div [ngClass]="{'active': isActive, 'disabled': !isActive}">Dynamic classes</div>

4. Custom Directives

You can also create your own directives to encapsulate reusable behavior. 


import { Directive, ElementRef, HostListener } from '@angular/core';

@Directive({
  selector: '[appHighlight]'
})
export class HighlightDirective {
  constructor(private el: ElementRef) {}

  @HostListener('mouseenter') onMouseEnter() {
    this.el.nativeElement.style.backgroundColor = 'yellow';
  }

  @HostListener('mouseleave') onMouseLeave() {
    this.el.nativeElement.style.backgroundColor = '';
  }
}


<p appHighlight>Hover over me to highlight</p>

In summary, Angular directives can be classified into:

  • Component Directives: have a template, control a view.
  • Structural Directives: change DOM structure (*ngIf, *ngFor).
  • Attribute Directives: change element appearance or behavior (ngStyle, ngClass).
  • Custom Directives: user-defined reusable behavior.

Forms

Forms in Angular are used to capture and process user input. Angular provides two main approaches for building forms: Template-driven forms and Reactive forms.

1. Template-driven Forms

Template-driven forms rely mostly on the template (HTML) to create forms. They are simpler and use directives such as ngModel for two-way data binding. 


<form #myForm="ngForm" (ngSubmit)="onSubmit(myForm)">
  <label>Name:</label>
  <input name="name" [(ngModel)]="userName" required>
  
  <label>Email:</label>
  <input name="email" [(ngModel)]="userEmail" required>
  
  <button type="submit">Submit</button>
</form>


export class AppComponent {
  userName = '';
  userEmail = '';

  onSubmit(form: any) {
  console.log('Form Submitted!', form.value);
  console.log(myForm.value);  // { name: 'John', email: 'john@example.com' }
  console.log(myForm.valid);  // true or false
  }
}

1. #myForm="ngForm"

#myForm creates a template reference variable called myForm.

The value "ngForm" tells Angular to bind the form element to Angular's NgForm directive.

This means myForm now references the Angular form object, which contains:

value → the form data (all input values).

valid / invalid → form validation status.

controls → all individual form controls.



2. (ngSubmit)="onSubmit(myForm)"
ngForm is a built-in Angular directive.

(ngSubmit) is an event binding that listens for the form’s submit event.

When the user clicks a submit button or presses Enter, Angular calls the onSubmit() method.

myForm (the template reference variable) is passed to the method, so you can access the form’s values and state in your component.

2. Reactive Forms

Reactive forms are more powerful and use FormControl, FormGroup, and FormBuilder in the component class to define the form structure and validation. 


import { Component } from '@angular/core';
import { FormBuilder, FormGroup, Validators } from '@angular/forms';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html'
})
export class AppComponent {
  myForm: FormGroup;

  constructor(private fb: FormBuilder) {
    this.myForm = this.fb.group({
      name: ['', Validators.required],
      email: ['', [Validators.required, Validators.email]]
    });
  }

  onSubmit() {
    console.log('Form Submitted!', this.myForm.value);
  }
}


<form [formGroup]="myForm" (ngSubmit)="onSubmit()">
  <label>Name:</label>
  <input formControlName="name">
  
  <label>Email:</label>
  <input formControlName="email">
  
  <button type="submit">Submit</button>
</form>

Template-driven forms are simpler for small forms, while reactive forms provide more control, flexibility, and scalability for complex forms.

HTTP Client

The HTTP Client in Angular is a service that allows you to make HTTP requests (GET, POST, PUT, DELETE) to communicate with back-end APIs. It is provided by the @angular/common/http module.

Steps to use HttpClient:

  1. Import HttpClientModule in your application module.
  2. Inject HttpClient service into your component or service.
  3. Use its methods to perform HTTP requests.

Example: GET Request


import { BrowserModule } from '@angular/platform-browser';
import { NgModule } from '@angular/core';
import { HttpClientModule } from '@angular/common/http';

@NgModule({
  declarations: [AppComponent],
  imports: [
    BrowserModule,
    HttpClientModule  // Import HttpClientModule here
  ],
  bootstrap: [AppComponent]
})
export class AppModule {}


import { Component } from '@angular/core';
import { HttpClient } from '@angular/common/http';

@Component({
  selector: 'app-root',
  template: `
    <h1>Users</h1>
    <ul>
      <li *ngFor="let user of users">{{ user.name }}</li>
    </ul>
  `
})
export class AppComponent {
  users: any[] = [];

  constructor(private http: HttpClient) {}

  ngOnInit() {
    this.http.get<any[]>('https://jsonplaceholder.typicode.com/users')
      .subscribe(data => {
        this.users = data;
      });
  }
}

Example: POST Request

this.http.post('https://jsonplaceholder.typicode.com/posts', {
  title: 'New Post',
  body: 'This is a new post',
  userId: 1
}).subscribe(response => {
  console.log('Post created:', response);
});

The HttpClient service also supports **interceptors**, **headers**, **query parameters**, and **error handling**, making it a powerful tool for communicating with APIs in Angular.

Index.html

The index.html file in an Angular project is the main HTML file that is served when your application loads. It acts as the **entry point** for the Angular app.

By default, it contains a <app-root> tag, which is the selector for your root component.


<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>MyAngularApp</title>
  <base href="/">
  <meta name="viewport" content="width=device-width, initial-scale=1">
</head>
<body>
  <app-root></app-root>   <!-- Root component selector -->
</body>
</html>

Key points about index.html:

  • The Angular app bootstraps on the <app-root> element.
  • All global scripts and styles can be included here, though Angular CLI recommends adding them via angular.json.
  • The <base href="/"> tag ensures that Angular routing works correctly.

Lifecycle Hooks

Lifecycle hooks in Angular are special methods that allow you to tap into key moments of a component’s lifecycle, such as creation, update, or destruction. They help you perform actions like initialization, cleanup, or responding to changes in inputs.

Common Angular Lifecycle Hooks:

  • ngOnInit() – Called once after the first ngOnChanges. Used for component initialization.
  • ngOnChanges(changes) – Called whenever an @Input property changes.
  • ngDoCheck() – Called during every change detection run. Useful for custom change detection.
  • ngAfterContentInit() – Called after projecting external content into the component.
  • ngAfterContentChecked() – Called after every check of projected content.
  • ngAfterViewInit() – Called after the component’s view (and child views) has been initialized.
  • ngAfterViewChecked() – Called after every check of the component’s view (and child views).
  • ngOnDestroy() – Called just before the component is destroyed. Used for cleanup.

Example:

import { Component, Input, OnInit, OnChanges, OnDestroy } from '@angular/core';

@Component({
  selector: 'app-sample',
  template: '<p>Sample component</p>'
})
export class SampleComponent implements OnInit, OnChanges, OnDestroy {
  @Input() data!: string;

  constructor() {
    console.log('Constructor called');
  }

  ngOnChanges(changes: any) {
    console.log('ngOnChanges:', changes);
  }

  ngOnInit() {
    console.log('ngOnInit called');
  }

  ngOnDestroy() {
    console.log('ngOnDestroy called');
  }
}

Lifecycle hooks allow you to **control component behavior at different stages**, making Angular components more predictable and manageable.

main.ts

The main.ts file in an Angular project is the **entry point** for bootstrapping the Angular application. It is responsible for initializing the app and telling Angular which module to load first.

Typical main.ts content:

import { platformBrowserDynamic } from '@angular/platform-browser-dynamic';
import { AppModule } from './app/app.module';

platformBrowserDynamic().bootstrapModule(AppModule)
  .catch(err => console.error(err));

Key points:

  • platformBrowserDynamic() – Creates a platform that can run the application in a browser.
  • bootstrapModule(AppModule) – Bootstraps the root module AppModule to launch the app.
  • Any errors during bootstrap are caught and logged in the console.

In short, main.ts is where Angular starts the application, loads the root module, and renders the root component in index.html.

Module

In Angular, a module is a container for a group of related components, directives, pipes, and services. Modules help organize the application into cohesive blocks of functionality and manage dependencies.

Key Points about Angular Modules:

  • Every Angular application has at least one module, the AppModule.
  • Modules are defined using the @NgModule decorator.
  • The declarations array lists components, directives, and pipes that belong to the module.
  • The imports array includes other modules whose exported classes are needed.
  • The providers array registers services that should be available application-wide or for this module.
  • The bootstrap array lists the root component(s) to load at application start.

Example: AppModule

import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { AppComponent } from './app.component';
import { ChildComponent } from './components/child/child.component';

@NgModule({
  declarations: [
    AppComponent,
    ChildComponent
  ],
  imports: [
    BrowserModule
  ],
  providers: [],
  bootstrap: [AppComponent]
})
export class AppModule { }

In this example:

  • AppComponent and ChildComponent are declared in the module.
  • BrowserModule is imported to provide essential browser features.
  • AppComponent is bootstrapped as the root component.

Modules in Angular provide **structure, encapsulation, and dependency management**, making large applications easier to maintain and scale.

Reactive Programming (RxJS)

RxJS (Reactive Extensions for JavaScript) is a library that allows you to work with asynchronous data streams in a powerful and flexible way. It is widely used in Angular for handling events, HTTP requests, and real-time data.

Key Concepts:

  • Observable: A stream of data that can emit multiple values over time.
  • Observer: An object that listens to the Observable and reacts to the emitted values.
  • Operators: Functions that allow you to transform, filter, or combine streams (like map, filter, merge).

Simple Example: Observable

// Import Component decorator and OnInit lifecycle hook from Angular core
import { Component, OnInit } from '@angular/core';
// Import Observable class from RxJS library
import { Observable } from 'rxjs';

// Define a new Angular component
@Component({
  selector: 'app-rxjs-demo', // HTML tag to use this component
  template: '
Check console for values
' // Simple template
})
// Export the component class and implement OnInit lifecycle hook
export class RxjsDemoComponent implements OnInit {

  // ngOnInit is called once when the component is initialized
  The $ sign in numbers$

  // By convention, developers often add a $ at the end of a variable to indicate that it is an Observable stream.
  // numbers$ is an Observable that emits three values in order: 1, 2, 3.
  // after emitting all values, it calls observer.complete() to signal that the stream has ended.
  // Nothing is actually executed until someone subscribes to it.
  
  
  ngOnInit() {
    // Create a new Observable that emits numbers
    const numbers$ = new Observable(observer => {
      observer.next(1); // Emit the first value
      observer.next(2); // Emit the second value
      observer.next(3); // Emit the third value
      observer.complete(); // Complete the Observable
    });

    // Subscribe to the Observable to listen for emitted values
    numbers$.subscribe({
      next: value => console.log('Number:', value), // Handle each emitted value
      complete: () => console.log('Observable completed') // Handle completion
    });
  }
}

Explanation in simple words for beginners
The Observable numbers$ emits values one by one.
The .subscribe() method listens to these values and runs the next function each time a value comes.
When the Observable is finished, the complete function runs.
The $ in numbers$ is just a convention to indicate it is an Observable.

Important point
Each observer.next(value) triggers the next callback immediately in the order the lines are written.
So Number: 1 is logged before Number: 2, which is logged before Number: 3, and then Observable completed is logged.

Observable vs Promise:

  • Promise: Handles a single value and executes immediately. Example: 
    const promise = new Promise(resolve => resolve('Hello Promise'));
promise.then(value => console.log(value));
  • Observable: Can emit multiple values over time and only runs when subscribed. Example: 
    const observable = new Observable(observer => {
  observer.next('First');
  observer.next('Second');
});
observable.subscribe(value => console.log(value));

In simple terms:

  • Promise: one-shot async result.
  • Observable: multiple async results over time, lazy, and powerful with operators.

✅ Example: Using RxJS with Axios
// Import required modules
import { from } from 'rxjs'; // Converts Promise to Observable
import axios from 'axios';

// Example function to fetch data
function getUserData() {
  // Axios returns a Promise
  const promise = axios.get('https://jsonplaceholder.typicode.com/users');

  // Convert the Promise into an Observable
  const users$ = from(promise);

  // Subscribe to the Observable
  users$.subscribe({
    next: response => console.log('Users:', response.data), // Handle success
    error: err => console.error('Error:', err),            // Handle error
    complete: () => console.log('Request completed')       // Handle completion
  });
}

// Call the function
getUserData();

Router Guards

Sometimes you need to protect routes (e.g., only logged-in users can access the dashboard). Angular provides Route Guards to control navigation.

Example: Authentication Guard

// auth.guard.ts
import { Injectable } from '@angular/core';
import { CanActivate, Router } from '@angular/router';

@Injectable({ providedIn: 'root' })
export class AuthGuard implements CanActivate {
  isLoggedIn = false; // Simulate login state

  constructor(private router: Router) {}

  canActivate(): boolean {
    if (this.isLoggedIn) {
      return true; // Allow access
    } else {
      this.router.navigate(['/']); // Redirect to home if not logged in
      return false;
    }
  }
}

// app-routing.module.ts (with guard)
const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'about', component: AboutComponent },
  { path: 'dashboard', component: DashboardComponent, canActivate: [AuthGuard] } 
];

With this setup:
- If isLoggedIn = true, user can access /dashboard.
- If isLoggedIn = false, user is redirected to /.

Summary:

  • Router: Lets users move between views without reloading the page.
  • Guard: Adds logic to allow/deny navigation (often used for authentication).

Bottlenecks

In Angular, bottlenecks are parts of your application that slow down performance, making the app feel laggy or unresponsive. Identifying and fixing bottlenecks is important to keep your app fast and smooth.

Common Bottlenecks

  • Too many change detections: Angular checks for changes in component data frequently. Large component trees or complex templates can slow this down.
  • Heavy computations in templates: Avoid putting expensive operations directly in the template (e.g., filters, calculations).
  • Excessive HTTP requests: Making too many API calls simultaneously can block rendering and slow down the app.
  • Large bundles: Bundling too much code or unnecessary libraries increases load time.
  • Unoptimized loops or DOM manipulations: Using inefficient loops or manipulating the DOM frequently can hurt performance.

How to Fix Bottlenecks

  • Use OnPush change detection where possible to reduce unnecessary checks.
  • Move heavy computations to component class or services instead of templates.
  • Use lazy loading for modules to reduce initial bundle size.
  • Optimize HTTP requests with caching, debouncing, or batching.
  • Use Angular trackBy in *ngFor loops to improve rendering performance.

By identifying bottlenecks and optimizing your code, Angular apps can run faster and provide a better user experience.

Lazy Loading

Lazy loading is a technique in Angular where modules are loaded only when they are needed, rather than loading everything at the start. This helps reduce the initial load time of your application and improves performance.

Why Use Lazy Loading?

  • Reduces the size of the initial bundle.
  • Improves app startup time.
  • Loads features only when the user navigates to them.

Basic Example

// app-routing.module.ts
import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';

const routes: Routes = [
  {
    path: 'dashboard',
    loadChildren: () => import('./dashboard/dashboard.module').then(m => m.DashboardModule)
  },
  {
    path: 'about',
    loadChildren: () => import('./about/about.module').then(m => m.AboutModule)
  }
];

@NgModule({
  imports: [RouterModule.forRoot(routes)],
  exports: [RouterModule]
})
export class AppRoutingModule { }

- The loadChildren property tells Angular to load the module only when the user navigates to that route. - Each feature module (like DashboardModule or AboutModule) can have its own components and routes.

Summary

  • Lazy loading improves performance by loading modules only when needed.
  • Use it for large applications with multiple feature modules.
  • Helps reduce initial bundle size and app startup time.

    • trackBy

    In Angular, trackBy is used with *ngFor to improve performance when rendering lists. It helps Angular identify which items in a list have changed, been added, or removed, instead of re-rendering the entire list.

    Why Use trackBy?

    • Reduces unnecessary DOM updates.
    • Improves performance for large lists.
    • Prevents losing component state inside repeated elements (like input values).

    Basic Example

    // component.ts
items = [
  { id: 1, name: 'Apple' },
  { id: 2, name: 'Banana' },
  { id: 3, name: 'Cherry' }
];

trackById(index: number, item: any) {
  return item.id;
}

    

      
  <li *ngFor="let item of items; trackBy: trackById">
    {{ item.name }}
  </li>

    Here, Angular uses trackById to identify each list item by its id. If the items array changes, Angular only updates the items that actually changed, instead of re-rendering the entire list.

    Summary

    • trackBy improves performance for *ngFor loops.
    • Always use a unique identifier (like id) in trackBy functions.
    • Especially useful for large lists or frequently changing data.

    Change Detection

    Change Detection in Angular is the mechanism that updates the view when the underlying component data changes. It ensures that the UI stays in sync with the component state.

    Old Way: Zone.js

    Angular traditionally used Zone.js to detect changes. Zone.js patches asynchronous operations (like events, promises, timers) to automatically trigger change detection.

    • Pros: Automatically updates the view when component data changes.
    • Cons: Can be inefficient for large apps because every async event triggers change detection for the entire component tree.
    // Example: old Zone.js behavior
// Every click or async task triggers full change detection
@Component({
  selector: 'app-old-cd',
  template: '<p>Count: {{ count }}</p><button (click)="increment()">Increment</button>'
})
export class OldCdComponent {
  count = 0;
  increment() { this.count++; }
}

    New Way: Signals

    Angular recently introduced Signals, a reactive primitive that tracks changes at a fine-grained level. With Signals, only the parts of the UI that actually depend on a value are updated — improving performance dramatically. 

    // Example using Signals
import { Component, signal, computed } from '@angular/core';

@Component({
  selector: 'app-signal-cd',
  template: '<p>Count: {{ count() }}</p><button (click)="increment()">Increment</button>'
})
export class SignalCdComponent {
  count = signal(0);          // Signal holding a number
  increment() { this.count.set(this.count() + 1); }
}

    With Signals:

    • Only the UI elements that depend on count are updated.
    • No global checks of the entire component tree.
    • Performance is better, especially for large apps.

    Summary

    • Zone.js: Automatic but triggers many unnecessary checks.
    • Signals: Fine-grained, reactive updates; more efficient.
    • Signals are the modern recommended way for change detection in Angular 16+.
