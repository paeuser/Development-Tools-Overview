RxJS Interview Questions

A quick-reference guide for common questions and concepts.

1. Core Concepts

What is RxJS?

RxJS (Reactive Extensions for JavaScript) is a library for reactive programming using Observables, to make it easier to compose asynchronous or callback-based code sequences. It is often used to handle events, HTTP requests, and other asynchronous data streams.

What is an Observable?

An Observable is a representation of a stream of data over time. It is "lazy," meaning it doesn't execute or emit values until a subscriber is attached. Observables can emit zero, one, or multiple values over their lifetime, and can either complete or error out.

What is a Subscriber?

A Subscriber, also known as an Observer, is an object with three methods: next(), error(), and complete(). It is the consumer of the values emitted by an Observable. When you call subscribe() on an Observable, you provide an Observer.

2. Operators

What are RxJS Operators?

Operators are pure functions that take an Observable as input and return a new Observable. They enable powerful transformations, filtering, and combinations of data streams without modifying the original source Observable. Operators are typically chained together using the pipe() method.

Difference between `map` and `switchMap`?

map transforms each value emitted by a source Observable and returns a new value. switchMap is a flattening operator. It maps each value to an inner Observable and then "switches" to the latest inner Observable, unsubscribing from the previous one. This is useful for scenarios like a search bar, where you only care about the result of the most recent query.

Explain `mergeMap` vs. `concatMap`.

mergeMap (or flatMap) subscribes to all inner Observables immediately and emits their values as they arrive. This can lead to concurrent operations. concatMap subscribes to the inner Observables one after another in a sequential order, waiting for each one to complete before subscribing to the next. This ensures order but can be slower.

3. Subjects

What is a Subject?

A Subject is a special type of Observable that can multicast, meaning it can emit values to multiple Observers simultaneously. It is also an Observer itself, so you can subscribe to it and also use its next(), error(), and complete() methods to manually control the stream.

Difference between `Subject` and `BehaviorSubject`?

A regular Subject does not have an initial value and only emits new values to subscribers who have subscribed after the value is emitted. A BehaviorSubject requires an initial value and will immediately emit the last known value (its initial value or the last emitted value) to any new subscriber.

When would you use `ReplaySubject`?

A ReplaySubject can replay a specified number of old values to new subscribers. For example, a ReplaySubject(3) would emit the last three values it received to any new subscriber. This is useful when you want new subscribers to have access to historical data from the stream.
