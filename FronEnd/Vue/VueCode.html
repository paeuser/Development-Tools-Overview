Reactive vs Ref (Vue 3 Composition API)

Explanation:

  • ref() is for a single primitive value (like number, string, etc.)
  • reactive() is for reactive objects (with multiple properties)
  • You must use .value when working with ref in JavaScript
  • Template automatically unwraps ref and reactive
<script setup>
import { ref, reactive } from 'vue'

// ref example (primitive)
const count = ref(0)
function incrementRef() {
  count.value++
}

// reactive example (object)
const state = reactive({
  count: 0

function incrementReactive() {
  state.count++

Computed Properties (Vue 3 Composition API)

Explanation:

Computed properties are reactive values derived from other reactive sources. They cache their results and only re-evaluate when dependencies change.

You define them using the computed() function, passing a getter function.

<script setup>
import { ref, computed } from 'vue'

const count = ref(0)

// Simple computed property
const doubled = computed(() => count.value * 2)

// Computed with a function inside
const greeting = computed(() => {
  function getMessage() {
    return count.value > 5 ? 'High count' : 'Low count'
  }
  return getMessage()
})

// External function used by computed
function evaluateCount(value) {
  if (value > 10) return 'Very High'
  if (value > 5) return 'High'
  return 'Low'
}

const externalGreeting = computed(() => evaluateCount(count.value))
</script>

<template>
  <div>
    <p>Count: {{ count }}</p>
    <p>Doubled: {{ doubled }}</p>
    <p>Greeting (internal fn): {{ greeting }}</p>
    <p>Greeting (external fn): {{ externalGreeting }}</p>
    <button @click="count++">Increment</button>
  </div>
</template>

    }
  },
  computed: {
    fullName() {

Watcher (Vue 3 Composition API)

Explanation:

A watch function observes reactive data sources (like refs or reactive objects) and runs a callback when the data changes. It's useful for performing side effects in response to state changes. If count changes 4 times, your watch callback will run 4 times, and you’ll see 4 console messages, one for each change. 

<script setup>
import { ref, watch } from 'vue'

const count = ref(0)

watch(count, (newValue, oldValue) => {
  console.log(`Count changed from ${oldValue} to ${newValue}`)
})

function increment() {
  count.value++
}
</script>

<template>
  <div>
    <p>Count: {{ count }}</p>
    <button @click="increment">Increment</button>
  </div>
</template>

watchEffect (Vue 3 Composition API)

Explanation:

watchEffect runs a function immediately and automatically tracks its reactive dependencies. Whenever any dependency changes, it re-runs the function. Unlike watch, you don’t specify the source explicitly. Useful for running side effects reactively without manually listing dependencies.

Here’s when watchEffect runs: Immediately as soon as it’s registered (runs the effect function once right away). Every time any reactive dependency used inside the effect function changes afterward. 

<script setup>
import { ref, watchEffect } from 'vue'

const count = ref(0)
const doubled = ref(0)

watchEffect(() => {
  doubled.value = count.value * 2
  console.log(`Count is ${count.value}, doubled is ${doubled.value}`)
})

function increment() {
  count.value++
}
</script>

<template>
  <div>
    <p>Count: {{ count }}</p>
    <p>Doubled: {{ doubled }}</p>
    <button @click="increment">Increment</button>
  </div>
</template>

Emit Events in <script setup>

Explanation:

In Vue 3's <script setup>, you use the defineEmits macro to declare which events a component can emit. It returns an emit function that you use to send events to the parent component.

This replaces the Options API's this.$emit method with a simpler, more explicit syntax.

<!-- ChildComponent.vue -->
<script setup>
const emit = defineEmits(['my-event'])

function handleClick() {
  emit('my-event', 'Hello from Child!')
}
</script>

<template>
  <button @click="handleClick">Click Me</button>
</template>

<!-- ParentComponent.vue -->
<script setup>
import { ref } from 'vue'
import ChildComponent from './ChildComponent.vue'

const message = ref('')

function handleMyEvent(payload) {
  message.value = payload
}
</script>

<template>
  <div>
    <ChildComponent @my-event="handleMyEvent" />
    <p>Message from child: {{ message }}</p>
  </div>
</template>

When the button in ChildComponent is clicked, it emits my-event with a message. The ParentComponent listens for this event and updates its local message reactive variable, which is displayed.

Global API Mounting Changes in Vue 3

In Vue 2, you created a Vue instance by calling new Vue() and mounting it directly: 

new Vue({
  el: '#app',
  render: h => h(App)
})

In Vue 3, the global API has changed. Instead of creating a new Vue instance, you create an app instance by calling createApp(), and then mount it explicitly with app.mount(): 

import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)
app.mount('#app')

This new approach enables more flexible app instances, supports multiple Vue apps on the same page, and improves plugin and component registration.

What is provide / inject and When to Use It?

provide and inject are a pair of Vue 3 APIs that allow you to pass data or dependencies from an ancestor component down to deeply nested child components without prop drilling (passing props through every intermediate component).

Use provide in a parent component to "provide" data, and inject in any descendant to "inject" or access that data.

How does the child receive the injected data? The key is that: ParentComponent uses provide('theme', theme) to make theme available to all of its descendants (children, grandchildren, etc.). ChildComponent uses inject('theme') to access that provided value. ChildComponent needs to be rendered inside ParentComponent's template (either directly or via slots).

Example:

<!-- ParentComponent.vue -->
<script setup>
import { provide, ref } from 'vue'

const theme = ref('dark')
provide('theme', theme)
</script>

<template>
  <div>
    <slot />
  </div>
</template>

<!-- ChildComponent.vue -->
<script setup>
import { inject } from 'vue'

const theme = inject('theme', ref('light')) // default to 'light' if not provided
</script>

<template>
  <p>Current theme is: {{ theme }}</p>
</template>

This avoids the need to pass the theme prop through every component in between.

When to use it: Use provide/inject when you need to share data or services (like global settings, plugins, or state) across many nested components without prop drilling.

Custom Directives in Vue 3

Vue 3 allows you to create your own custom directives to manipulate the DOM directly. Custom directives are useful when you need low-level DOM access or want to encapsulate reusable DOM behavior.

Unlike built-in directives like v-if or v-model, custom directives let you define your own behavior for elements.

Creating a simple custom directive:

<script setup>
import { ref, onMounted } from 'vue'

// Define the directive
const focus = {
  mounted(el) {
    el.focus()
  }
}
</script>

Using the directive in the template:

<template>
  <input v-focus placeholder="Input will be focused on mount" />
</template>

To use the directive globally, you can register it on the app instance: 

import { createApp } from 'vue'
import App from './App.vue'

const app = createApp(App)

app.directive('focus', {
  mounted(el) {
    el.focus()
  }
})

app.mount('#app')

What the user experiences:

When the page loads, the cursor automatically appears inside the input box. This means the user can start typing immediately without clicking the input first. This makes the form feel quicker and easier to use.

Accessing Template Refs in the Composition API

In Vue 3's Composition API, you can use the ref function together with the ref attribute in the template to get a direct reference to a DOM element or a child component instance.

This is useful when you want to manipulate the DOM directly or call methods on a child component.

Example: Accessing a DOM element with a template ref

<template>
  <input ref="inputRef" placeholder="Focus me with button" />
  <button @click="focusInput">Focus Input</button>
</template>

<script setup>
import { ref } from 'vue'

// Create a template ref
const inputRef = ref(null)

// Define a method to focus the input element
function focusInput() {
  if (inputRef.value) {
    inputRef.value.focus()
  }
}
</script>

In this example, inputRef is linked to the <input> element via the ref attribute. When the button is clicked, the focusInput method calls the native focus() method on the input element.

What is the Purpose of toRefs and toRef?

In Vue 3's Composition API, toRefs and toRef are utility functions that help you convert reactive objects or specific properties into refs. This is useful for better reactivity and destructuring.

toRefs

When you have a reactive object (created by reactive()), destructuring it directly breaks reactivity. To avoid this, use toRefs to convert each property into a ref, so reactivity is preserved. 

import { reactive, toRefs } from 'vue'

const state = reactive({
  count: 0,
  name: 'Vue'
})

// Without toRefs, destructuring breaks reactivity
const { count, name } = toRefs(state)

// Now count and name are refs you can use in the template or watch

toRef

Use toRef when you want to create a ref for a single property of a reactive object. 

import { reactive, toRef } from 'vue'

const state = reactive({
  count: 0,
  name: 'Vue'
})

const countRef = toRef(state, 'count')

// countRef.value will stay reactive and reflect changes in state.count

These utilities help maintain reactivity when working with destructured reactive objects.

<Suspense> in Vue 3

The <Suspense> component in Vue 3 is used to handle components that rely on asynchronous data or setup. It allows you to show a fallback UI (like a loading spinner or message) while waiting for async components or data to be ready.

Use cases:

  • Lazy-loaded components
  • Components using async setup()
  • Waiting for external data sources before rendering

Syntax:

<Suspense>
  <template #default>
    <AsyncComponent />
  </template>

  <template #fallback>
    <div>Loading...</div>
  </template>
</Suspense>

In this example, while <AsyncComponent> is still loading or resolving asynchronous setup code, Vue will display the fallback template ("Loading...").

<!-- AsyncComponent.vue -->
<template>

</template>

shallowRef vs ref in Vue 3

Both ref and shallowRef are used to create reactive references in Vue 3, but they differ in how deeply they track reactivity.

ref

Creates a deep reactive reference. If you pass an object or array, Vue makes all its nested properties reactive too. 

import { ref } from 'vue'

const state = ref({ count: 0 })

state.value.count++  // triggers reactivity updates

shallowRef

Creates a shallow reactive reference. Only the top-level value is reactive; nested properties are not reactive. 

import { shallowRef } from 'vue'

const state = shallowRef({ count: 0 })

state.value.count++  // will NOT trigger reactivity updates

Use shallowRef when you want to avoid deep reactivity for performance reasons or when dealing with large objects that rarely change deeply.

Example comparing both:

<template>
  <div>
    <h3>Using ref</h3>
    <p>Count: {{ deepState.count }}</p>
    <button @click="deepState.count++">Increment deep</button>

    <h3>Using shallowRef</h3>
    <p>Count: {{ shallowState.value.count }}</p>
    <button @click="shallowState.value.count++">Increment shallow</button>
  </div>
</template>

<script setup>
import { ref, shallowRef } from 'vue'

const deepState = ref({ count: 0 })
const shallowState = shallowRef({ count: 0 })
</script>

While templates are easier and more declarative, render functions offer more flexibility and control — useful for advanced dynamic rendering or when you want to write JSX/TSX.

Handling Form Input and Validation in Vue 3

Vue 3 makes handling form inputs straightforward with two-way binding via v-model. For validation, you can write custom logic or use libraries like Vuelidate or vee-validate.

<template>
  <form @submit.prevent="handleSubmit">
    <div>
      <label for="email">Email:</label>
      <input
        id="email"
        type="email"
        v-model="email"
        @blur="validateEmail"
      />
      <span style="color: red;" v-if="errors.email">{{ errors.email }}</span>
    </div>

    <div>
      <label for="password">Password:</label>
      <input
        id="password"
        type="password"
        v-model="password"
        @blur="validatePassword"
      />
      <span style="color: red;" v-if="errors.password">{{ errors.password }}</span>
    </div>

    <button type="submit">Submit</button>
  </form>
</template>

<script setup>
import { ref, reactive } from 'vue'

const email = ref('')
const password = ref('')

const errors = reactive({
  email: '',
  password: ''
})

function validateEmail() {
  errors.email = ''
  if (!email.value) {
    errors.email = 'Email is required.'
  } else if (!/\S+@\S+\.\S+/.test(email.value)) {
    errors.email = 'Email must be valid.'
  }
}

function validatePassword() {
  errors.password = ''
  if (!password.value) {
    errors.password = 'Password is required.'
  } else if (password.value.length < 6) {
    errors.password = 'Password must be at least 6 characters.'
  }
}

function handleSubmit() {
  // Validate all fields before submitting
  validateEmail()
  validatePassword()

  if (!errors.email && !errors.password) {
    alert('Form submitted successfully!')
    // Proceed with form submission logic here
  }
}
</script>

Explanation:

  • v-model binds input values to reactive refs.
  • @blur triggers validation functions when the user leaves an input field.
  • Validation functions update the errors reactive object with messages if inputs are invalid.
  • The form submission handler runs all validations and proceeds only if no errors exist.

This approach gives you full control over validation logic. For larger projects, consider validation libraries like vee-validate or Vuelidate for more features and easier validation handling.

When used on an element or component, v-memo takes an array of reactive dependencies as its argument. Vue will only re-render that element if one or more of these dependencies have changed since the last render.

  count.value++
}
</script>

In this example, the <p> element with v-memo="[count]" will only re-render when count changes. If other unrelated reactive state changes, Vue skips re-rendering this element.

Vue 3 Reactivity Caveats

Vue 3's reactivity system is powerful but there are some important caveats to keep in mind when working with reactive data.

1. Reactivity on New Properties

Adding new properties to a reactive object after its creation is not reactive by default. You need to use Vue.set in Vue 2 or create reactive objects properly in Vue 3. 

<script setup>
import { reactive } from 'vue'

const state = reactive({ count: 0 })

// Adding a new property after creation won't be reactive:
state.newProp = 'hello' // This won't trigger reactivity
</script>

To make new properties reactive, initialize them upfront or use ref or reactive properly.

2. Reactivity Does Not Track Array Index Changes

Modifying array elements by direct index assignment does not trigger reactivity. 

<script setup>
import { reactive } from 'vue'

const arr = reactive([1, 2, 3])

arr[0] = 10 // Vue won't detect this change reactively
</script>

Use array methods like push, splice, or replace the entire array to trigger updates.

3. Using ref for Primitive Values

Primitive values like strings, numbers, booleans must be wrapped with ref to be reactive. 

<script setup>
import { ref } from 'vue'

const count = ref(0)

count.value++ // Updating count with .value triggers reactivity
</script>

Remember to access and update the value via .value when using refs.

Summary

  • Initialize all reactive properties upfront for reactivity.
  • Use Vue's reactive array methods to update arrays.
  • Use ref for primitives and access with .value.

const schema = yup.object({

const { handleSubmit } = useForm({ validationSchema: schema })
const { value: email, errorMessage: emailError } = useField('email')

const onSubmit = handleSubmit((values) => {
  console.log('Form Submitted:', values)
})

    <button type="submit">Submit</button>
  </form>
</template>

<style scoped>

  color: red;
  font-size: 0.9rem;
}
</style>

<script setup>

Extract logic into reusable composables using the Composition API. 

// useAuth.js
import { ref } from 'vue'

export function useAuth() {
  const isAuthenticated = ref(false)

  const login = () => {
    // Logic here...
    isAuthenticated.value = true
  }

  return { isAuthenticated, login }
}

// LoginForm.vue
<script setup>
import { useAuth } from '@/composables/useAuth'

Share state across deeply nested components without prop drilling.

// Deep Child
<script setup>
import { inject } from 'vue'
const theme = inject('theme')
</script>

These components expose logic via slots or scoped slots but don’t render markup themselves.

Authentication Integration

In modern Vue 3 apps, authentication often involves integrating with external identity providers (e.g., Okta, Auth0, Azure AD) using OAuth 2.0 or OpenID Connect (OIDC). Vue handles authentication by managing access tokens, redirecting users, and securing routes with navigation guards or composables.

1. Token-Based Authentication (Overview)

  • Frontend handles login redirect and receives access/ID tokens (JWT)
  • Tokens stored in memory or secure cookies
  • Tokens sent via Authorization: Bearer in API requests

2. Example: OAuth / OIDC with vue3-oidc-client

Here’s a real-world integration using the vue3-oidc-client library with OpenID Connect:

import { UserManager } from 'oidc-client-ts'

export const oidc = new UserManager({
  authority: 'https://your-identity-provider.com',
  client_id: 'your-client-id',
  redirect_uri: 'http://localhost:3000/callback',
  response_type: 'code',
  scope: 'openid profile email',
  post_logout_redirect_uri: 'http://localhost:3000'
})

export const login = () => oidc.signinRedirect()
export const logout = () => oidc.signoutRedirect()
export const getUser = () => oidc.getUser()

// main.js
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'

createApp(App).use(router).mount('#app')

3. Router Guard for Protected Routes

// router/index.js
import { createRouter, createWebHistory } from 'vue-router'
import Home from '../views/Home.vue'
import Dashboard from '../views/Dashboard.vue'
import { getUser } from '../auth'

const routes = [
  { path: '/', name: 'Home', component: Home },
  { 
    path: '/dashboard', 
    name: 'Dashboard', 
    component: Dashboard,
    meta: { requiresAuth: true }
  },
  {
    path: '/callback',
    name: 'Callback',
    beforeEnter: async (to, from, next) => {
      await oidc.signinRedirectCallback()
      next('/')
    }
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

router.beforeEach(async (to, from, next) => {
  if (to.meta.requiresAuth) {
    const user = await getUser()
    if (!user || user.expired) {
      return login()
    }
  }
  next()
})

export default router

4. Protected API Requests with Axios

// axios.js
import axios from 'axios'
import { getUser } from './auth'

const api = axios.create({
  baseURL: 'https://api.yourdomain.com'
})

api.interceptors.request.use(async (config) => {
  const user = await getUser()
  if (user && user.access_token) {
    config.headers.Authorization = `Bearer ${user.access_token}`
  }
  return config
})

export default api

6. Best Practices

  • Never store tokens in localStorage (vulnerable to XSS)
  • Use memory, HTTP-only cookies, or session management via a backend
  • Protect routes with `beforeEach` guards or layout-based auth wrappers
  • Refresh tokens securely via silent auth or refresh token flow
  • Use HTTPS in all environments with authentication

State Management with Vuex

Vuex is a state management library for Vue.js applications. It helps you manage shared state across multiple components in a centralized store, making it easier to maintain and debug large applications.

Instead of passing data through many layers of components, Vuex allows you to keep the state in one place and access or modify it from anywhere in your app using actions, mutations, and getters.

Simple Vuex Store Example

// store.js
import { createStore } from 'vuex';

export const store = createStore({
  state() {
    return {
      count: 0
    };
  },
  mutations: {
    increment(state) {
      state.count++;
    }
  },
  actions: {
    increment({ commit }) {
      commit('increment');
    }
  },
  getters: {
    count(state) {
      return state.count;
    }
  }
});

Using Vuex in a Vue 3 Component

<template>
  <div>
    <p>Count: {{ count }}</p>
    <button @click="increment">Increment</button>
  </div>
</template>

<script>
import { computed } from 'vue';
import { useStore } from 'vuex';

export default {
  setup() {
    const store = useStore();

    const count = computed(() => store.getters.count);

    const increment = () => {
      store.dispatch('increment');
    };

    return {
      count,
      increment
    };
  }
};
</script>

This example shows how Vuex stores the count state centrally and how the component accesses and updates that state using getters and actions.
