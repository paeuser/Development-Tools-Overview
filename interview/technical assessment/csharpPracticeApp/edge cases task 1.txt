✅ Likely Interview Follow-up Questions
🔹 1. Can you solve it without converting to a binary string?

Why they ask: To test your understanding of bitwise operations.

What they want: A solution using bit shifts like N >> 1 and N & 1.


        class Solution
        {
            public int solution(int N)
            {
                int maxGap = 0;         // Will store the longest binary gap found
                int currentGap = 0;     // Counts zeros in the current gap

                // Step 1: Skip all trailing zeros because gaps must be *surrounded* by 1s
                while ((N > 0) && ((N & 1) == 0))  
                {
                    N >>= 1;            // Shift bits right by 1 (remove the least significant bit)
                }

                // Step 2: Now process the bits one by one until N becomes zero
                while (N > 0)
                {
                    if ((N & 1) == 0)   // Check if current least significant bit is 0
                    {
                        currentGap++;    // If yes, increase the zero count in current gap
                    }
                    else                 // Current bit is 1, so the gap ended here
                    {
                        if (currentGap > maxGap)   // Check if the current gap is longest so far
                        {
                            maxGap = currentGap;   // Update maxGap if needed
                        }
                        currentGap = 0;            // Reset zero count for the next gap
                    }

                    N >>= 1;           // Shift bits right by 1 to move to the next bit
                }

                return maxGap;         // Return the length of the longest binary gap found
            }
        }


        Explanation for a beginner:

        N & 1: This checks if the rightmost bit is a 1 or 0.

        N >>= 1: This moves all bits one place to the right, effectively dividing the number by 2 and dropping the rightmost bit.

        We skip trailing zeros at the start because zeros after the last 1 do not form a valid binary gap.

        Every time we see a 1 after some zeros, we check if those zeros form the longest gap.



You’d loop through bits and track gaps directly without using Convert.ToString(N, 2).
🔹 2. What is the time and space complexity of your solution?

Expected answer:

    Time complexity: O(log N) — since we loop through binary digits

    Space complexity:

        O(log N) if using a string (Convert.ToString(...))

        O(1) if using bitwise solution (no string creation)

🔹 3. Can you explain what a binary gap is in your own words?

They want to hear a clear, confident explanation like:

    A binary gap is a sequence of consecutive zeros in a number’s binary representation, surrounded by 1s on both sides.

🔹 4. What are some edge cases you considered?

You should mention:

    All 1s (no gaps): N = 15 → 1111

    Trailing zeros: N = 32 → 100000

    Small numbers: N = 1, 2, 3

    Multiple gaps: N = 529

🔹 5. What would change if we allowed negative numbers?

Current problem assumes N > 0. For negatives, C# uses two’s complement, so binary representation becomes more complex and gaps don’t make as much sense.

So you'd explain:

    “Binary gap is undefined for negative numbers in this context because of two’s complement and infinite leading 1s.”
