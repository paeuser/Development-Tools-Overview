Common Web Vulnerabilities

1. Cross-Site Scripting (XSS)

  • What is it? Malicious scripts injected into web pages viewed by other users.
  • Impact: Can steal cookies, session tokens, or perform actions as the user.
  • How to fix: Always escape user input before displaying it (e.g., using HTML escaping or sanitization).

Example (safe display):


<div>User says: <span id="output"></span></div>

<script>
  // attacker-controlled input (example)
  const userInput = "<script>alert('xss')</script> Hello <b>world</b>";

  // FIX: insert as text so any HTML is not interpreted/executed
  document.getElementById("output").textContent = userInput;
</script>

Yes — after escaping, the alert will not execute because escaping replaces special characters with safe equivalents:

Character Escaped form Meaning
< &lt; Displays as < instead of starting a tag
> &gt; Displays as >
& &amp; Displays as &
" &quot; Displays as "
' ' Displays as '

2. Cross-Site Request Forgery (CSRF)

  • What is it? Tricks a user into performing actions they didn’t intend to on a site where they’re authenticated.
  • Impact: Can change user data, make purchases, or perform admin actions without consent.
  • How to fix: Use anti-CSRF tokens and verify requests originate from your site.

3. SQL Injection

  • What is it? Attackers inject malicious SQL into input fields to manipulate your database.
  • Impact: Can read, modify, or delete data; sometimes gain full control of the server.
  • How to fix: Use prepared statements or parameterized queries and validate all input.

Best Practices

  • Validate and sanitize all user input.
  • Use frameworks and libraries that protect against these attacks.
  • Keep software and dependencies up to date.
  • Educate developers on secure coding practices.
